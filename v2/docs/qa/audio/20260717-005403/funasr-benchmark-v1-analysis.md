# FunASR 固定中文语料基准 v1

- 执行时间：2026-07-17（UTC+8）
- 执行位置：生产机临时目录，只调用当前 LightTTS 与 FunASR；未创建房间、未写数据库、未修改生产配置或服务。
- 正例：8 条；负控：静音、低幅底噪各 1 条。
- 并发：4 条独立 FunASR WebSocket 流。
- 传输：100 ms PCM 分片，`pace=1.0` 按实时节奏发送。`pace` 只改变 WebSocket 传输节奏，不改变音频中的实际语速、韵律或停顿。
- 证据类型：正例均为当次 LightTTS 合成后回转 FunASR 的 `tts_roundtrip` 证据；它不能替代真人麦克风录音 CER。

## 生产调用链审计

当前真实链路为：浏览器采集 PCM → `/ws/rooms/{code}/asr` 鉴权 → 按比赛快照选择 FunASR endpoint → 发送 `START` / `LANGUAGE:zh-CN` / PCM / `STOP` → 解析 partial/final → VAD、置信度和文本质量过滤 → final 写入 `Speech` 与 `TranscriptSegment` → 房间广播。

应用桥接层已有以下保护：席位与控制租约校验、每个 speech 单活流、比赛服务快照、流状态每秒复核、静音/低置信度/过短/异常符号/重复字符拒绝、旧设备 final 拒绝。固定基准直接连接 FunASR，用于测量识别服务本身；`scripts/verify_parallel_asr_streams.py` 与 API 测试另行覆盖房间桥接、持久化、重复连接和旧设备隔离。

| 指标 | 结果 | 评价 |
|---|---:|---|
| 微平均 CER | 4.27% | TTS 回转准确率较高，但不是人声 CER |
| 宏平均 CER | 4.40% | 个别困难语料错误明显 |
| 删除率 | 1.42% | 数字、长句存在吞字 |
| 插入率 | 0.28% | 较低 |
| 句首锚点通过率 | 75.0% | 未达稳定发布期望 |
| 句尾锚点通过率 | 87.5% | 边界专测失败 |
| 首个 partial p50 / max | 3279 / 4105 ms | 明显过慢；字幕用户会感到滞后 |
| STOP 后 final p50 / max | 672 / 1345 ms | 可接受，但长句仍超过 1.3 秒 |
| 静音/低噪误识别 | 0 / 2 | 本轮通过 |
| 4 并发串流 | 0 / 8 | 本轮未发现串流 |
| 工程评分 | 89.85 / 100 | 仅限本次 TTS 回转证据集，不是 ASR 发布门槛结论 |

评分公式：CER 准确度 60 分 + 句首/句尾 10 分 + 删除/重复 10 分 + partial/final 延迟 10 分 + 负控 5 分 + 并发隔离 5 分。完整阈值和各分项见 JSON 的 `score_basis`。本轮首个 partial 超过 2500 ms，因此 partial 延迟分为 0；准确度、负控和并发隔离拉高了总分。

## 逐项主要问题

| 语料 | CER | 主要证据 |
|---|---:|---|
| 标准中文 | 0.00% | 完整识别 |
| 数字单位 | 6.25% | “三点五秒”识别为“三点”，出现吞字 |
| 人名术语 | 5.88% | “竺可桢”识别为“竹可珍”，句首锚点失败 |
| 中英混读 | 5.56% | `ChatGPT` 识别为近似英文片段，术语稳定性不足 |
| 多音字 | 2.78% | “作出”识别为“做出”；语义近似但严格数据文本不一致 |
| 句首句尾锚点 | 11.90% | “句首/青松/句尾/白鹭”多处同音替换，首尾锚点均失败 |
| 相似与重复 | 0.00% | 完整识别，未产生额外重复二元组 |
| 长句 | 2.83% | 中段短语删除，final 延迟 1345 ms |

同一 v1 语料的前一轮临时合成回转曾得到 3.13% micro CER，本次保留证据的最终轮为 4.27%。这表明 TTS 随机性和/或 ASR 推理波动不可忽略；后续应对同一真人录音重复识别至少 5 次，报告均值、P95 与方差，而不能只取单次最好结果。

## 0–100 分解释与发布门槛

89.85 分只表示“本次 LightTTS→FunASR 回转样本在当前公式下的工程表现”。真人麦克风会引入设备频响、距离、口音、语速、教室混响、多人串音、键盘噪声和网络抖动，这些均未被 TTS 回转覆盖。因此：

1. 真人麦克风固定语料 CER 仍缺直接证据，ASR 发布门槛尚未完成。
2. 首个 partial p50 3.279 秒，即使最终 CER 较低，也会造成实时字幕明显滞后，应单独列为高优先级性能问题。
3. 当前并发结论只证明 4 个 FunASR 连接的本轮文本未互串；房间、用户、持久化和广播隔离仍以应用桥接测试为证据，不能由本基准替代。
4. 慢速/快速真人语音必须使用实际变速或真人录音；调整 `pace` 只能模拟网络发送节奏，不能证明不同语速下的识别质量。
