# 轻微杂音与撕裂音再次复核

日期：2026-07-19

## 结论

本轮没有修改 MOSS、音色提示、LiveKit、Opus、AudioWorklet、播放缓冲或实时滤波。

用户仍能主观听到少量杂音后，重新扫描了生产数据库中最近 30 段 AI 原始 WAV，并复核
生产运行参数、当前音色映射和浏览器播放器文件。隔离问题音色后的最近 11 段正式 TTS
均没有削波、孤立脉冲或超过 `0.3` 的硬采样跳变；生产 MOSS 仍严格运行在已验收的
`decode_chunk_frames=3`、`initial_chunk_frames=6`、`do_sample=true`、同步 decoder 配置。

因此，当前证据不足以支持在可靠链路上叠加低通、去点击、限幅、提高 Opus 码率或扩大
起播缓冲。这些处理不能修复模型音色中偶发的轻微粗糙感，反而会增加声音发闷、首声
超过 3 秒或重新出现欠载卡顿的风险。

## 决策

保留当前可靠基线，不做收益不明确的热路径改动。若再次听到明显问题，应记录房间号、
席位和大致发言时间；系统保存对应原始 WAV，可将源音频与同一时刻的 RTP 丢包、
concealment 和浏览器输出对齐。只有确认异常稳定出现在某个仍在使用的音色或传输阶段
后，才进行单音色替换或独立 A/B，而不全局修改播放链路。
