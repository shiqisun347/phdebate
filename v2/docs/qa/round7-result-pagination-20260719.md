# Round 7：赛果逐字稿分页与长时间线可用性验证

日期：2026-07-19

## 本轮范围

本轮只处理比赛结果和历史记录的读取性能、分页一致性与结果页可用性。未修改 DebateStage、TTS、ASR、MOSS、LiveKit、AudioWorklet、PCM 播放器或实时音频传输代码。

## 修复内容

### 服务端逐字稿分页

- `/api/rooms/{code}/result` 和 `/api/matches/{match_id}/history` 支持：
  - `speech_page`
  - `speech_page_size`，范围 1–200，默认 100
  - `speech_cursor`
- 响应保留原有 `speeches` 数组，并新增 `speech_pagination`，不会破坏仍读取原字段的旧客户端。
- 第一页读取最近一批发言，但返回给浏览器的每一页仍按时间正序排列；后续游标向更早记录移动，符合结果页“加载更早发言”的操作含义。
- 游标使用应用密钥 HMAC 签名，并绑定：
  - 比赛 ID
  - 页大小
  - 边界发言的 `created_at + id`
  - 首次读取时的快照总数
  - 游标协议版本
- 不接受篡改游标、跨比赛游标或中途更改页大小，统一返回 422。
- 同一时间戳使用发言 ID 作稳定次序，避免重复或遗漏。
- 比赛仍在进行并产生新发言时，已签发的“更早记录”游标不会因最新记录插入而漂移。
- 同一条游标链沿用首次读取的总数，避免翻到最后一页时出现“已加载 5 / 6、却没有更多按钮”的矛盾状态；刷新后再纳入新增发言。

### 数据库索引与迁移

- Speech 模型新增复合索引：`(match_id, created_at, id)`。
- Alembic 新增 `0025_speech_result_pagination`。
- upgrade/downgrade 均检查表和索引现状，可在已有数据库上重复安全执行。

### 结果页

- 比赛摘要中的“发言数”改用 `speech_pagination.total`，不再把当前加载数组长度误报为整场总数。
- 逐字稿标题显示“已加载 n / total”。
- 提供明确的“加载更早发言”按钮。
- 新旧页按发言 ID 去重，再按 `created_at + id` 稳定排序。
- 刷新赛果或收到较新的房间序列时，会继续读取分页，直到刷新前已经展开的发言仍被保留；不会悄悄退回第一页。
- 并发刷新和分页响应使用请求序号及游标校验，旧响应不能覆盖较新的状态。
- 比赛结果时间线取消 `600px` 内嵌滚动，所有归档事件进入普通页面文档流；单场控制台的紧凑时间线仍保持原有滚动方式。

## 验证场景

- 页码兼容读取和签名游标读取。
- 相同时间戳的稳定顺序。
- 翻页过程中追加新发言，无重复、无游标漂移。
- 游标篡改、页大小变化和跨比赛复用被拒绝。
- 公开房间匿名读取、私密房间匿名/非参与者拒绝。
- 不同房间和比赛之间的逐字稿隔离。
- `legacy=true` 的旧比赛仍可读取空音频 URL、旧阶段键和历史内容。
- 0025 在模拟已有数据库上重复 upgrade/downgrade。
- 前端总数、加载更早、去重、稳定顺序和刷新保留已加载页。
- 结果时间线使用专用正常文档流 class，桌面和手机页面不再出现难发现的嵌套滚动区域。

## 兼容性说明

- 默认 100 条以内的历史比赛仍一次返回全部发言，字段形状保持不变。
- 超过默认页大小时，旧客户端会看到最近 100 条；新结果页会显示权威总数并允许继续加载全部更早记录。
- 完整、不可分页截断的研究导出仍使用比赛 archive 接口，不改变归档完整性。
