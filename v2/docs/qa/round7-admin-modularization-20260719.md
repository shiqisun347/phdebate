# Round 7 管理后台模块化与按需加载验收

日期：2026-07-19

## 目标

将原先集中在 `app/admin/page.tsx` 的后台页面拆成清晰的业务模块，降低维护和回归风险；低频模块与弹窗仅在管理员实际打开时加载。保持既有路由、接口、视觉、文案、键盘语义和权限逻辑不变。

本轮属于后台代码结构与前端加载性能改造，没有修改 DebateStage、TTS、ASR、MOSS、LiveKit、AudioWorklet、PCM、音频传输或浏览器播放代码。

## 实施结果

- `app/admin/page.tsx` 从 2404 行降至 1172 行，保留身份验证、状态协调、请求去重和写操作编排。
- 新增共享后台类型与审计标签：`components/admin/admin-module-types.ts`。
- 拆分为六个业务模块：
  - 赛事、赛季与题库；
  - 自动比赛流程；
  - AI 辩手、裁判与服务配置；
  - 媒体及比赛归档；
  - 比赛结果复核；
  - 管理员审计日志。
- 题目、密码重置、流程版本和赛果复核弹窗移入独立文件。
- 使用 `next/dynamic` 按当前标签页加载业务模块；弹窗只有在状态打开时才渲染和加载。
- 每个动态模块提供可读的加载状态，保留 `aria-busy`、`aria-live`、可聚焦表格区域及原有表单标签。
- 页面数据仍按标签页懒加载并防止重复并发请求；代码分包不改变 API 调用时机。

## 风险控制

- 未改变 REST URL、请求体、幂等逻辑或权限检查。
- 未改变标签名称、视觉类名、按钮文案、表格与弹窗可访问名称。
