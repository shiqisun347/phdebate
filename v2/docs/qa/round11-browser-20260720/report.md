## 问题

### ISSUE-001：网络恢复后仍显示“本次操作可能尚未提交”的过期错误

| 字段 | 内容 |
|---|---|
| 严重程度 | Medium |
| 类别 | UX / 弱网恢复 |
| 页面 | `/rooms/925030/lobby`（QA 房间，测试结束后关闭） |
| 视频 | `/tmp/phdebate-round11-browser/videos/issue-001-stale-network-error.webm` |

**现象**

学生在离线状态认领席位时，页面会正确提示网络断开和操作未提交；网络恢复且 WebSocket 状态已经回到“实时连接”后，这条操作失败提示仍长期保留。此时席位确实未被认领，但页面同时呈现“连接正常”和“请检查网络后重试”，容易让学生误判仍未恢复联网，或重复操作。

**复现步骤**

1. 登录后进入一个等待中的房间，确认顶部状态为“实时连接”。证据：`/tmp/phdebate-round11-browser/screenshots/issue-001-step-1.png`。
2. 断开浏览器网络并点击空席，页面显示断线提示与“本次操作可能尚未提交”。证据：`/tmp/phdebate-round11-browser/screenshots/issue-001-step-2.png`。
3. 恢复网络，页面自动重连并重新显示“实时连接”。
4. 观察右侧错误仍存在。证据：`/tmp/phdebate-round11-browser/screenshots/issue-001-result.png`。

**建议**

- 将写操作错误绑定到一次具体操作，并在用户重新发起同类操作、页面获得最新房间快照或连接成功后清除。
- 若需要保留失败历史，应改为可关闭的通知，并明确显示“连接已恢复；上一次认领没有提交，请重新点击席位”。

### ISSUE-002：“跳到主要内容”只滚动页面，没有把键盘焦点移入主内容

| 字段 | 内容 |
|---|---|
| 严重程度 | Low |
| 类别 | Accessibility / 键盘导航 |
| 页面 | `/` |
| 视频 | `/tmp/phdebate-round11-browser/videos/issue-002-skip-focus.webm` |

**现象**

键盘用户首次按 Tab 可以正确聚焦“跳到主要内容”，按 Enter 后 URL 变为 `#main-content` 且页面发生滚动，但 `document.activeElement` 回到 `BODY`，没有进入 `<main>`。因此下一次 Tab 仍可能从页头导航继续，跳过链接没有真正减少键盘操作量，屏幕阅读器也缺少明确的焦点上下文切换。

**复现步骤**

1. 在首页刷新后按一次 Tab，“跳到主要内容”获得焦点。证据：`/tmp/phdebate-round11-browser/screenshots/issue-002-step-1.png`。
2. 按 Enter，页面滚动到主区域。证据：`/tmp/phdebate-round11-browser/screenshots/issue-002-result.png`。
3. 浏览器运行态证据为 `hash=#main-content`、`activeTag=BODY`、主内容未聚焦。

**建议**

- 为主内容容器增加可编程聚焦能力（例如 `tabIndex={-1}`），并在 skip link 激活后显式调用 `focus()`。
- 保留清晰的 `:focus-visible` 样式，并用键盘和屏幕阅读器回归验证下一次 Tab 从主内容中的首个控件继续。

## 已通过验证

### 身份、隐私与权限

- 匿名访问等待中的房间大厅和观战路径均无法读取房主姓名、席位与准备状态，统一进入无权访问错误页。
- 登录用户可通过六位房间号或直链进入房间；错误房间号保留在弹窗内并明确提示“房间不存在”。
- 普通参赛者访问 `/rooms/:code/control` 时只能看到只读观战投影，页面明确提示只有房主或管理员可进入控制台；没有出现暂停、跳过或终止权限。
- 普通用户直接访问 `/admin` 被重定向至赛事大厅。
- 同账号第二设备可正常登录；在个人中心执行“退出其他设备”后，第二设备刷新即被重定向至 `/login?next=/me`，当前设备继续有效。
- 所有登录失败均使用统一“账号或密码错误”，没有泄露账号是否存在。

### 4v4 多人房间

- 房主必须主动选择具体辩位后才能创建房间，没有隐式默认席位。
- 第二名学生通过直链进入后可认领不同阵营席位；两端刷新后房间号、辩题、席位、在线与准备状态一致。
- 对“确认准备”执行快速双击后最终只进入一次“已准备”，没有被第二次请求反向取消。
- 房主在真人未全部准备时无法开始；界面提供明确的“移出”恢复入口，本轮实际验证了关闭尚未开始的房间。
- 关闭房间后，另一名学生刷新被送回赛事大厅，并看到“房间已关闭”的可理解提示。

### 1v1 创建、加入与恢复

- 训练赛支持题库辩题与自定义辩题；本轮自定义辩题能够完整进入大厅。
- 未选辩位时“创建比赛”保持禁用；选择正方一辩后才能提交。
- 第二名学生可认领、主动释放并重新看到可认领空席；两端状态同步。
- 仅房主一人准备、另一席为空时，页面正确显示“1 个空席将由 AI 补齐”，主操作变为“锁定席位并开始”。本轮没有点击该按钮。
- 结果页在比赛尚未生成时明确显示“该房间还没有比赛记录”，没有空白页或 500。

### 弱网与错误恢复

- 浏览器离线后实时状态立即切换为“正在重连”，并显示“网络连接已断开，恢复联网后将自动重连”。
- 离线认领席位不会产生幽灵占位；恢复联网后服务器权威状态仍为空席。
- 网络恢复后 WebSocket 能自动回到“实时连接”。遗留错误提示见 ISSUE-001。
- 页面加载、建房、认领、准备、释放、关闭、登录失败和不存在房间均未观察到未捕获 JavaScript 异常。

### 个人中心、排行榜与结果

- 新用户个人中心正确展示 0 积分、0 历史、0 进行中，并提供继续比赛空态、历史空态、修改密码及撤销其他设备入口。
- 被关闭且从未开赛的 QA 房间不会错误计入历史比赛或累计场次。
- 匿名排行榜可访问；赛事和赛季选择器有可访问名称；无有效计分比赛时显示完整空态，而不是空表格。

### 响应式与视觉

- 在 `390×844`、`768×1024`、`1440×900` 下检查了赛事大厅与房间大厅；登录页检查了 390px，排行榜、个人中心和控制台检查了 1440px。
- 390px 首页与房间大厅的 `documentElement.scrollWidth` 均等于 `innerWidth`，没有横向溢出。
- 手机导航菜单可打开、可用 Escape 关闭，`aria-expanded` 状态同步变化。
- 长辩题在 390px 房间卡片中正常换行；席位、房间号、准备按钮和关闭操作保持可点击且无重叠。
- 页面风格、层级、间距和两套赛事卡片保持一致，本轮未发现阻断性的裁切、错位或不可读对比度问题。
