## 当前版本发现的问题

### ISSUE-001：提前结束比赛后仍停留在辩论页，并显示互相矛盾的终止状态

| 字段 | 内容 |
|---|---|
| 严重度 | P1 / High |
| 分类 | 功能、状态一致性、导航 |
| 版本 | `round51-full-flow-ux-asr-20260722` |
| 房间 | `600584` |
| 页面 | `/rooms/600584/debate` |
| 证据 | [终止后的辩论页](browser-fullflow-round2-20260722/screenshots/round51-result-terminated.png)、[手动进入的结果页](browser-fullflow-round2-20260722/screenshots/round51-result-direct.png) |

**现象**

房主在自由辩论阶段打开“比赛操作”，点击“提前结束比赛”并二次确认后：

1. 服务端已将比赛标记为终止，页面顶部显示“比赛已终止”。
2. 浏览器没有进入 `/rooms/600584/result`，仍停留在 `/debate`。
3. 页面同时显示“自由辩论”“正方当前轮次”“比赛尚未开始”“00:00”等互相矛盾的信息。
4. 未提交的文字发言入口仍显示“文字内容仍在本页 / 继续文字发言”，容易误导用户继续操作已经终止的比赛。
5. 手动打开 `/rooms/600584/result` 后，结果页能够正常显示“比赛已终止”。

**复现步骤**

1. 房主创建并开始 1v1 比赛。
2. 比赛进入自由辩论阶段。
3. 打开底部“比赛操作”。
4. 点击“提前结束比赛”，再点击“确认提前结束”。
5. 观察页面没有跳转，并出现上述矛盾状态。

**期望行为**

- 终止接口成功后立即清理本地发言草稿、麦克风状态和自由辩论队列。
- 将客户端状态投影为 `terminated`，禁止继续发言或举手。
- 自动 `replace` 到 `/rooms/:code/result`，避免浏览器后退返回已失效的比赛控制态。
- 若结果数据仍在生成，结果页应显示短暂的“正在整理比赛记录”，而不是回退为“比赛尚未开始”。

## 体验与产品结论

- Round 51 的比赛页已经形成较清晰的浅色比赛舞台，信息层级和移动端底部主操作优于旧版。
- 发言权限文案能明确说明“轮到你”“当前轮到另一方”“主持提示中”“比赛暂停”等原因，用户较容易判断下一步。
- 单行字幕卡符合大屏/电视剧字幕的阅读方式，移动端不会遮挡主要舞台。
- 匿名观众隐私边界符合当前要求：比赛过程中和结果页均不展示完整文字稿。
- 当前最需要修复的是终止后的客户端状态收敛与自动进入结果页，否则房主会误以为终止失败或比赛状态损坏。

## Round 52 修复回执

上述“终止后停留在比赛页”的 P1 已在 Round 52 修复并部署：

- 终止、完成或待复核时，如存在尚未提交的真人文字发言，页面会明确提示“比赛已结束，本轮文字尚未提交”。
- 用户可以保留并复制草稿，或点击“放弃未提交内容并查看结果”；系统不再静默丢弃文字，也不会无限阻止进入结果页。
- 新增组件回归测试，相关 11 项测试通过；生产 Web 发布为 `round52-terminal-text-recovery-20260722`，构建通过。

该修复完成后，本报告原有 P1 已关闭。由于该缺陷涉及终止边界而非正常比赛状态机，1v1 与 4v4 正常完整比赛验证结果不受影响。
