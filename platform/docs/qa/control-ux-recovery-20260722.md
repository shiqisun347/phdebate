# 房主与参赛用户控制体验修复

日期：2026-07-22  
范围：赛前大厅、辩手比赛页、自由辩论举手、单场比赛控制台  
未修改：API、ASR、TTS、LiveKit、公开赛事页面

## 本轮解决的问题

### 1. 开赛后的“等待”含义不清

此前房主点击开始后，比赛舞台仍提示“所有席位准备完成后将自动开赛”，计时器显示 `--:--`。这会让用户误以为仍有人未准备，进而返回大厅或重复点击。

现在：

- 大厅始终显示一张“当前操作”卡，按未入座、未准备、已准备、房主可开赛、等待他人等状态给出唯一下一步。
- 开赛确认明确说明：席位锁定后，系统会连接实时语音、播放预设开场提示，然后自动进入第一阶段。
- 比赛准备页改为“正在连接比赛服务”。
- 准备阶段不再伪装成比赛倒计时，计时区显示“自动 / 准备完成后直接开场”。
- 明确提示“无需再次操作”，减少重复点击和误退出。

### 2. 举手队列遮挡舞台且操作入口漂移

此前自由辩论举手面板固定在右上方，移动端会遮挡赛况；队列和主操作混在一个较大的浮层中。

现在：

- 举手操作固定在舞台底部、主控制栏上方，桌面和手机位置一致。
- 主按钮始终可见，明确显示“举手申请下一轮”或“取消举手（第 N 位）”。
- 队列详情默认收起，点击后查看完整顺序；观战模式默认展开但保持只读。
- 顶部摘要直接显示“你已排在第 N 位”“已有 N 人举手”或“某某已获得下一轮发言权”。
- 禁用按钮下方持续显示服务端返回的具体原因，不依赖鼠标悬停。
- 保留服务端权威顺序、三秒申请窗口、幂等请求和错误后安全重试。

### 3. 房主控制的风险与禁用原因不够直观

现在：

- 控制台底部固定操作条会根据当前状态解释为何不能暂停或跳过，例如“真人辩手正在发言；结束并提交后才能暂停或跳过”。
- 准备阶段明确说明系统会自动连接服务和开场，不要求房主处理。
- 操作提交中明确提示“请勿重复点击”。
- 暂停、恢复、重置发言、重试异常步骤、跳过和终止继续由服务端状态决定权限。
- 重置、重试、跳过和终止的确认对话框增加键盘焦点约束、Escape 关闭和关闭后焦点恢复，避免键盘操作落到背景页面。
- 断开 WebSocket 时仍保留 REST 应急控制；接口幂等键继续避免重复操作。

## 产品设计原则

- 正常比赛由自动流程推进，房主控制只用于异常恢复和现场应急。
- 每个页面优先展示“当前状态 + 下一步”，避免把内部服务状态暴露为需要用户判断的技术选项。
- 真人正在发言时不允许暂停或跳过，防止已采集音频与服务端文字提交状态分叉。
- 不把不可逆操作和日常操作混为一个主按钮；跳过与终止仍需要二次确认。
- 手机端的高频主操作保持在拇指可达的底部区域，详情按需展开。

- 定向 Vitest：`103 passed, 21 skipped`。
- 覆盖：大厅角色下一步、开赛确认、准备状态、发言权限与禁用原因、举手申请/取消/排序/倒计时、暂停/恢复、失败重试、AI 发言重置、跳过、终止、断线操作与权限跳转。
- ESLint：修改文件无 error；现有 `debate-stage` 测试和历史 Hook 依赖仅保留原有 warning。
- Next.js production build：通过，TypeScript 与所有动态房间路由构建成功。

## 后续生产验收重点

- 在真实自由辩论阶段分别用桌面和手机确认底部举手条不遮挡字幕、文字记录按钮和比赛操作。
- 实测房主在真人发言、AI 发言、手动暂停、服务异常暂停和自动评审五种状态下看到的主操作与说明一致。
- 真实开赛时记录从点击确认到第一条预设主持音播放的等待时间，确认准备页不会长期停留。

## 增量：真人断线不再由 AI 自动接管

按 2026-07-22 更新后的比赛规则，Web 控制面已完成以下收敛：

- 辩手比赛页和房间控制台均移除“放弃本场并由 AI 接替”的正常操作入口及其确认流程。
- 真人断线时，舞台和控制台同时提示：席位保留 60 秒；超时后比赛自动暂停，不会安排 AI 接替；真人返回后由房主确认继续。
- 控制台底部状态条在有人断线时优先显示宽限规则，避免房主误以为比赛仍会自动推进。
- 历史 `ai_substitute` 数据仅作为旧比赛兼容状态显示为“历史只读席位”，不再作为当前比赛机制宣传。
- 历史席位恢复面板改为“历史只读席位恢复”，明确新规则与 60 秒暂停策略。
- 比赛事件文案将旧 `seat.ai_substituted` 标记为历史只读状态，将 `presence.expired` 明确为“断线宽限到期，比赛暂停”。
- 赛事详情的“通用约定”同步更新为 60 秒后自动暂停、真人返回后由房主继续，不再写 AI 接替后续轮次。

- Next.js production build：通过。
- ESLint：无 error；保留原有 Hook 依赖和测试变量 warning。
