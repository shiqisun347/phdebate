# Round 10 前端产品体验与性能审计

日期：2026-07-20

## 范围与边界

本轮聚焦大规模学生参赛时最常使用的个人中心、排行榜、4v4 房间大厅、单场控制台和系统管理后台。设计判断以“高并发赛事指挥台”为核心：关键信息先于设置项、状态可扫描、危险操作有明确边界、手机端不依赖横向拖动才能理解核心数据。

以下可靠语音路径保持冻结，未作任何修改：

- `components/debate-stage.tsx`
- `lib/audio/*`
- `public/worklets/*`
- LiveKit、AudioWorklet、PCM、MOSS/TTS 与浏览器播放代码

## 已修复问题

### 排行榜

- 修复非默认积分赛事可能短暂显示 `daily-4v4` 预热榜单的问题。只有实际选择默认赛事时才接受并行预热响应，其他赛事必须使用赛事与赛季完全匹配的请求。
- 切换赛事或赛季后立即清除旧榜单，避免请求过程中把上一个赛季的数据错误地标在新筛选条件下。
- 动态参数执行 URL 编码。
- 手机端把宽度至少 650px 的横向表格改为纵向成绩卡。排名、辩手、积分、战绩、平均评分和场次在 390px 宽度下可直接阅读。
- 增加表格 caption、移动端数据标签，以及带下一步说明的空榜状态。

### 4v4 房间大厅

- 辩题区增加“已准备真人 / 真人总数”“在线真人数”“AI 待补席位数”，房间成员无需逐席统计即可判断能否开赛。
- 每个真人席位同时显示准备和在线状态，避免把离线但已准备的成员误认为仍在房间。
- 抢座请求进行中立即锁定所有空席按钮并显示“正在认领席位”，防止快速双击或多个按钮连点产生重复请求。
- 准备状态保存期间显示明确进度。
- 将可选麦克风预检移动到席位与开赛信息之后；进入大厅时优先看到辩题、人员、席位和准备状态，预检功能本身未修改。

### 单场控制台

- 真人正在发言时同时禁止“暂停”和“跳过当前阶段”。此前“跳过”仍可点击，存在截断真人发言并造成状态错位的风险。
- 真人席位恢复申请只有在申请者已经重新连接比赛页后才能批准；离线时按钮显示“等待辩手连接”。这与服务端恢复前置条件保持一致，避免管理员反复收到可预防的错误。
- 自动流程尚无事件时显示解释性空状态，不再留下一个看似加载失败的空面板。

### 个人中心

- 分页、恢复申请和主动刷新期间显示可被读屏软件感知的更新状态。
- 恢复/撤销按钮显示当前操作进度，避免学生在网络较慢时重复提交。
- 密码修改失败使用 `alert`，成功使用 `status`，纠正错误信息优先级。

### 系统管理后台

- 房间监管可一次清除房间号/辩题、状态和数据类型三个筛选条件。
- 用户管理可一次清除搜索条件并返回第一页。
- 用户和房间表格在请求期间暴露 `aria-busy`，不会把旧行误读为已更新结果。
- 重复出现的“控制、观战、标记 QA、停用、重置密码、管理员授权”等操作加入房间号或真实姓名，键盘和读屏用户能够辨别按钮作用对象。
- 筛选清除和行内操作均明确使用非提交按钮，降低后续嵌入表单时的意外提交风险。

## 性能与实现原则

- 继续保留后台模块的动态加载，不把低频管理功能加入首屏包。
- 排行榜仍并行请求赛事、赛季和默认榜单，没有引入串行 waterfall。
- 使用请求序号阻止迟到响应覆盖当前选择；新测试覆盖默认赛事预热响应污染另一赛事的场景。
- 没有增加运行时依赖，也没有添加全局事件监听器或新的常驻轮询。
- 移动排行榜使用同一份语义表格数据和 CSS 响应式布局，没有维护第二套列表状态。

## 生产黑盒问题闭环

根据 `round10-browser-20260720/report.md` 的生产复测，继续完成以下修复：

- 建房不再隐式选中正方一辩。真人必须主动选择席位后才能创建；席位使用原生 radio/fieldset 语义，辅助技术能够读取组名和选中状态，并显示“你将作为”确认摘要。
- 不存在、已删除、已取消或已关闭的房间不再描述为临时故障。错误页使用唯一 `h1`，隐藏无意义的重试按钮，并允许直接输入另一个六位房间号。
- 普通成员或匿名用户进入控制台时不再静默跳转，也不会短暂显示应急按钮。页面先解释正在切换为只读观战，观战页再显示一次“不具备控制权限”的非敏感提示。
- 390px 导航菜单按钮固定为 `44×44px`，不再受周边 flex 空间压缩。

## 后续建议

- 在生产部署后用 390×844、768×1024 和 1440×900 三种视口复核排行榜卡片、4v4 八席大厅和后台五列筛选工具栏。
- 后续若后台单表达到数万行，应维持服务端分页，并将当前 100 行默认分页按真实设备性能数据评估为 50 行；本轮未在缺少生产性能证据时改变 API 分页契约。
- 赛事运营可补充“仅看异常房间”和“仅看待恢复席位”快捷筛选，但应由后端提供可分页筛选，而不是把全部房间拉到浏览器后过滤。
