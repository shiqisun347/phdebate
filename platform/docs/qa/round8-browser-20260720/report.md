## 已确认问题

### ISSUE-001：跨页面导航继承大厅滚动位置，赛事详情首屏被跳过

| 字段 | 内容 |
|---|---|
| 严重程度 | Medium |
| 分类 | UX / navigation / accessibility |
| URL | `https://117.50.192.216/` → `/competitions/daily-4v4` |
| 复现视频 | [issue-001-repro.webm](videos/issue-001-repro.webm) |

**现象**

用户在赛事大厅向下浏览赛事卡片，然后点击“查看规则”进入赛事详情时，新页面继承大厅的滚动位置。详情页会直接落到底部内容区，标题、赛事概览、“立即参赛”和标签导航都被跳过；在复现状态中标签还会落在固定顶部导航下面，自动化和实际点击均可能命中顶部品牌链接。

成熟产品的跨路由导航应默认将新页面恢复到顶部；只有浏览器“返回”时才应恢复上一页滚动位置。

**复现步骤**

1. 打开赛事大厅，定位到页面下方的赛事卡片。
   ![大厅下方赛事卡片](screenshots/issue-001-step-1b.png)
2. 点击 4v4 卡片中的“查看规则”。
   ![进入详情后的页面](screenshots/issue-001-step-2.png)
3. 观察详情页：页面位于 `scrollY=541`，而不是顶部；标题和参赛入口不在视口内，标签靠近固定顶部栏。
   ![错误结果](screenshots/issue-001-result.png)

**建议验收**

- 从任意大厅滚动位置进入赛事详情，目标页面 `scrollY` 应为 0。
- 浏览器返回大厅时仍可恢复原滚动位置。
- 键盘焦点应落在详情主标题或主内容区域，不应被固定导航覆盖。

### ISSUE-002：390px 移动端赛事标签逐字换行

| 字段 | 内容 |
|---|---|
| 严重程度 | Medium |
| 分类 | Responsive UI / readability |
| URL | `https://117.50.192.216/competitions/daily-4v4` |
| 复现视频 | N/A（静态可见问题） |

**现象**

在 390×844 的常见手机视口中，四个赛事详情标签仍强制并排。标签文字被压缩成两至三行，部分接近逐字竖排，例如“排行榜”“观战列表”“规则说明”，显著降低扫读效率和专业感。

![390px 标签换行](screenshots/issue-002.png)

**建议验收**

- 390px 宽度下标签保持单行；可采用横向可滚动标签栏、紧凑字号/间距，或两列分段控件。
- 当前标签必须持续可见，并保留至少 44px 的触控高度。
- 320、360、390、430px 宽度下均不应逐字换行或截断语义。

### ISSUE-003：大厅与赛事详情对“可观战比赛”采用不一致的过期规则

| 字段 | 内容 |
|---|---|
| 严重程度 | Medium |
| 分类 | Functional / content consistency |
| URL | `/` 与 `/competitions/daily-4v4` |
| 复现视频 | N/A（跨页面静态状态对照） |

**现象**

同一测试时段，大厅的 4v4 卡片和“公开比赛”区显示 `0 场可观战`，但 4v4 赛事详情仍显示 `1 场可观战`，并在“观战列表”中继续公开房间 `551958`。该房间的比赛记录显示其在 2026-07-19 14:16 左右暂停，本轮检查时已超过 11 小时，不应被赛事详情继续作为活跃观战入口推广。

这会让学生在大厅看到“暂无公开比赛”，进入赛事详情后又看到一场长期暂停的比赛，破坏状态可信度，也让长期废弃房间占据赛事入口。

1. 大厅 390px 完整截图中，两个赛事卡片均显示 `0 场可观战`，公开比赛为空。
   ![大厅显示零场](screenshots/home-mobile-390x844.png)
2. 打开 4v4 赛事详情的“观战列表”，仍可看到暂停房间 `551958`。
   ![赛事详情仍列出旧房间](screenshots/competition-watch-tab.png)

**建议验收**

- 大厅赛事计数、公开比赛列表、赛事详情计数、赛事详情观战列表必须复用同一套公开房间筛选策略。
- 超过公开暂停保留窗口的房间从所有公开入口同步消失，但仍允许用户通过历史记录或直接链接访问结果/恢复入口。
- 为筛选规则增加同一时间点、同一房间集合的契约测试，避免不同 API 漂移。
