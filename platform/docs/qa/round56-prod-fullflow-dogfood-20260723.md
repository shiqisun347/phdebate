### ISSUE-001：自由辩论提示音和等待发言会提前消耗总时长与单轮时长

| 字段 | 内容 |
|---|---|
| 严重级别 | **High** |
| 分类 | 功能 / 计时 / 比赛公平性 |
| 页面 | `https://117.50.192.216/rooms/141327/debate` |
| 视频 | N/A（静态计时状态可直接复现） |
| 当前状态 | **生产修复前证据；开发侧已本地修复，待部署后复测** |

**现象**

自由辩论配置显示总计时 4 分钟、当前轮次 30 秒。进入自由辩论后，系统先播放约 7 秒阶段提示，辩手尚未点击“开始发言”，计时已经下降；继续等待时总计时和单轮计时持续减少。证据截图中，第一位辩手还处于“开始发言”状态，但总时长只剩约 `03:45`，本轮只剩 `00:15`。

**预期**

系统提示音不应占用辩论时间；至少第一轮应在真人明确开始发言后再启动总计时与单轮计时。每次换方后的准备/举手/三秒提示也需定义清楚，不能在无人发言时持续扣减有效发言时间。

**复现步骤**

1. 创建 1v1 双真人房间并完成双方立论。
2. 系统自动进入“自由辩论”，播放约 7 秒提示音。
3. 不点击“开始发言”，等待提示音结束。
4. **观察：** 页面仍显示等待正方开始发言，但总计时和本轮计时已明显减少。  
   ![自由辩论未开始即计时](assets/round56-prod-fullflow/screenshots/issue-001-free-debate-clock-before-first-speech.png)

**影响**

真人思考、麦克风授权或提示音播放都会直接侵占比赛时间，可能使首位辩手尚未发言本轮就自动耗尽，属于完整比赛流程和公平性的高优先级问题。

### ISSUE-002：普通辩手的“比赛操作”菜单实际只有退出页面，命名与交互层级误导

| 字段 | 内容 |
|---|---|
| 严重级别 | **Medium** |
| 分类 | UX / 控制逻辑 |
| 页面 | `https://117.50.192.216/rooms/141327/debate` |
| 视频 | N/A（静态菜单状态） |

**现象**

非房主辩手底部固定栏显示“比赛操作”。打开后只有“仅退出比赛页面”一个可执行项，没有任何比赛控制。用户会自然理解“比赛操作”为暂停、举手、发言或其他赛程操作，打开后却只看到退出，增加一次无意义的弹窗和理解成本。

**预期**

普通辩手应直接显示清晰的“退出页面”或将该按钮命名为“更多”；只有房主才显示“比赛控制”。同一位置不应对两种权限使用相同但语义明显不同的标题。

**证据**

### ISSUE-003：AI 固定发言阶段整轮没有逐句字幕，页面长时间只显示占位文案

| 字段 | 内容 |
|---|---|
| 严重级别 | **High** |
| 分类 | 功能 / 实时字幕 / 可访问性 |
| 页面 | `https://117.50.192.216/rooms/733951/debate` |
| 视频 | N/A（整轮稳定复现） |

**现象**

1v1 人机房间中，AI 正方一辩开始发言后，LiveKit 音轨已接收并产生可听音频遥测，但中央字幕从发言开始直到阶段结束始终只显示“当前发言暂时没有逐句字幕”。AI 发言结束后进入反方阶段，“文字记录”面板也只按当前阶段显示 `0 条已完成发言`，辩手无法在赛中回看刚结束的 AI 论点。

**预期**

参赛辩手页面应像电视字幕一样只显示一行、持续滚动更新的当前短语；AI 文本本来由 Agent 流式产生，应同步投影为字幕。匿名观众仍需保持不可见文字稿，两者权限不应混为一谈。

**证据**

AI 已进入“正在发言”，倒计时明显推进，但字幕仍为空：

![AI 发言无逐句字幕](assets/round56-prod-fullflow/screenshots/issue-003-ai-timer-before-caption-audio.png)

**影响**

教室、嘈杂会场、听障用户或暂时静音的辩手无法理解 AI 发言，也无法据此准备回应；这会直接影响人机辩论的核心体验。

### ISSUE-005：同一次真人断线暂停，在观战页被错误描述为“临时服务异常”

| 字段 | 内容 |
|---|---|
| 严重级别 | **Medium** |
| 分类 | 状态一致性 / 内容 / 运维可观察性 |
| 页面 | `https://117.50.192.216/rooms/733951/watch` |
| 视频 | N/A（断线 60 秒后的稳定状态） |

**现象**

**预期**

观战投影应保留脱敏后的准确暂停原因，例如“参赛者暂时离线，比赛已安全暂停”，而不是把正常的断线保护误报为系统故障。

## 已通过行为

- 注册后可直接进入赛事大厅；第二位用户通过房间链接认领空席，双方实时在线/准备状态能在约 1 秒内同步。
- 房主开始比赛前有明确的二次确认，确认后自动锁定席位；1v1 人机房间空席自动生成 AI 辩手，普通用户无需配置模型参数。
- 双真人固定立论和总结阶段均在当前真人点击发言后计时，等待期间不扣减完整发言时长。
- 麦克风权限被拒绝时显示具体浏览器权限提示，并提供文字完成本轮发言；提交内容会进入结果页完整文字记录。
- 自由辩论中对方实际发言后，下一方可以举手、取消举手并查看排队顺序；被选中席位会在舞台明确标识。
- 房主暂停后，两位辩手和匿名观众均同步为暂停状态；暂停 5 秒后倒计时保持不变。普通辩手操作菜单没有暂停、继续或终止权限。
- 真人断线后席位仍是“真人离线”，页面明确说明 60 秒后自动暂停且不会由 AI 接替；超时后自动暂停，重连后没有自动恢复，房主手动继续成功。
- 匿名观众赛中只能看到脱敏舞台和举手队列，不能举手、发言或查看文字；赛后结果页不返回完整辩论文字记录。
- 两个房间均完成 AI 裁判并自动进入结果页，参赛者个人中心可返回历史比赛；房间 `141327` 生成 4 条发言，房间 `733951` 生成 9 条发言。
- 房间 `733951` 在断线暂停前后的 AI/真人发言、举手队列、裁判结果和事件时间线均保持在本房间内，没有影响房间 `141327` 的已完成结果。

## 性能与控制台观察

- 创建房间和进入大厅的可感知响应低于 1 秒；确认开赛到辩论舞台可交互约 3 秒。
- 人机房间结果时间线显示多个 AI 轮次从“发言开始”到“实时语音播放开始”为约 1–2 秒；浏览器端采样也观察到首个可听音频事件，满足本轮样本的 3 秒目标。
- 采样 WebRTC 音轨 `packets_lost=0`、`jitter≈4ms`，平均 jitter buffer 约 `218–239ms`。本轮没有观察到网络丢包导致的音轨中断；由于运行在无声 Headless Chrome，不能据此断言主观音质、杂音或撕裂完全合格。
- AI 正方总结从流式播放开始到完整音频就绪约 74 秒，但播放在开始生成后约 1 秒已启动，说明当前链路是边生成边播放而不是等待完整音频。
- 训练点评开始后约 8 秒生成最终裁判结果并跳转结果页。
- 业务动作未观察到 JavaScript exception 或 4xx/5xx 失败。匿名新页面出现一次浏览器自动播放限制警告，页面提供“开启比赛声音”按钮，属于预期浏览器策略处理。
- AI 固定阶段虽然音频已经流式播放，字幕仍全程为空；这是 ISSUE-003，不应被音频性能通过掩盖。

## 覆盖限制与下一轮建议

- 本轮没有使用真实物理麦克风，因此 ASR 双流式、电视剧式真人字幕、端到端打断和真实噪声环境仍需桌面浏览器人工复测。
- 本轮没有执行 4v4 完整赛和房主“提前结束比赛”，原因是完成两条核心 1v1 流程后遵守不再新增/占用房间的约束。
- 部署 ISSUE-001 修复后，应优先复测：提示音不扣时、无人发言不扣总时长、真人实际发言只累计真实时长、AI 发言时按实际播放时长累计、暂停/断线期间不累计。
- 修复 ISSUE-003 后应验证：参赛辩手看到单行短语字幕，匿名观众仍完全看不到文字稿，阶段结束后参赛者可按规则回看本场已完成发言。
