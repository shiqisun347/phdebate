# Web 旧轮次输入、移动端控制与结果可读性修复（Round 55）

## 范围

本轮只修改 Web，不修改 API、比赛引擎、LiveKit、WebRTC 或字幕单行投影。依据生产黑盒报告 `browser-controls-caption-round55-20260722.md` 修复以下问题：

- 文字兜底和语音识别后的人工核对不能跨阶段、跨发言记录提交。
- 真人尚未点击“开始发言”时，浏览器必须显示并保持完整冻结时长。
- 390×844 下举手队列、文字恢复入口和固定底栏不能占用同一块空间。
- 运行页面不再把自动提示称为“主持人”。
- 结果页长篇文字记录提高对比度和连续阅读体验。

## 实现结果

### 1. 文字输入绑定 `speech_id + stage_key`

`TextSpeechFallback` 现在创建一次文字发言时同时保存：

- 服务端返回的 `speech_id`；
- 创建时的 `stage_key`、阶段名称和本人席位；
- 当前发言记录是否曾被服务端实时状态确认。

出现以下任一情况后，提交入口立即失效：

- 当前阶段 key 改变；
- 当前席位改变；
- `active_speech.id` 被另一条发言替换；
- 绑定发言收到 `completed`、`interrupted` 或 `timed_out` 事件；
- 已观察到的绑定发言从服务端活动状态消失；
- 比赛结束。

过期草稿不会静默丢失。页面自动打开“上一轮文字已停止提交”，保留只读内容供复制核对，并明确要求清除后按当前轮次重新建立发言。客户端不会再向 `/speech/finish` 提交这份旧内容。

语音 ASR 的人工核对同样保存 `speechId`、`stageKey` 和阶段名称。提交前、提交进行中、提交响应返回后三个时间点都会重新核对实时房间状态。WebSocket 在提交期间报告阶段或发言失效时，浏览器会取消请求并保留只读文字，不会把页面当作提交成功。

### 2. 真人发言倒计时语义

Web 已接入服务端 `current_stage.awaiting_human_start`：

- 浏览器本地倒计时停止递减；
- 显示完整冻结时长，例如 `02:00`；
- 计时器标签为“开始发言后计时”；
- 无障碍名称为“完整发言时间 02:00，点击开始发言后计时”；
- 舞台提示明确显示“张三点击‘开始发言’后正式计时”；
- 辩手开始后状态移除，倒计时才正常运行。

桌面和手机共用同一个 `DebateStage` 投影，因此不会出现两个视口使用不同计时语义的情况。

### 3. 390×844 底部安全区

- 固定辩手控制栏继续占据底部专属区域。
- 自由辩论队列固定在控制栏上方，并限制最大高度；内容过多时只在队列内部滚动。
- 文字恢复 CTA 在手机端移到舞台顶部右侧，不再浮在控制栏和举手队列之间。
- 交互式举手队列默认折叠，首屏只保留轮到阵营、队列人数、窗口时间和主操作。

这三个功能现在使用不同垂直区域，不再形成生产截图中的三层重叠。

### 4. 系统提示而非主持人

运行舞台会把后端兼容文案统一投影为用户可理解的系统文案：

- “主持人正在播报下一环节” → “系统正在播放阶段提示”；
- 提示阶段倒计时标签改为“阶段提示音”；
- 提示音时间不再标成“本环节剩余”。

该转换只影响展示，不改变服务端阶段 key、提示音或自动赛程逻辑。

### 5. 结果页文字对比度

非舞台页面的完整文字记录正文改为深蓝灰 `#304966`，保留元信息的次级层级；正文使用 `15px / 1.82` 行高并支持原始换行和长词折行。修订前正文为浅色 `#c3cbe0`，在白色卡片上明显发虚。

## 自动化证据

- 针对性回归：`79 passed, 21 skipped`（`DebateStage` 与文字兜底）。
- Web 全量单元/组件测试：`345 passed, 21 skipped`，共 `51` 个测试文件全部通过。
- ESLint：`0 errors`；现有警告不阻断构建。
- Next.js production build：通过。

新增或更新的关键覆盖：

- 文字草稿在阶段切换后只读且不会发出 finish 请求；
- 同阶段另一 `speech_id` 替换后旧草稿失效；
- ASR 核对在房间完成、发言超时、发言中断、阶段切换时停止提交；
- 提交请求进行中收到终局状态时不把旧内容视为成功；
- `awaiting_human_start` 保持 `02:00`，8 秒后仍不递减，开始发言后 5 秒变为 `01:55`；
- 自动阶段提示页面不出现“主持人”，计时器明确为提示音时长。

## 部署后复验

本报告证明当前源码和构建产物通过自动化门禁；生产发布后仍需使用真实双用户房间复验：

1. 在固定发言临近结束时打开文字输入，等待自动切换阶段，确认提交按钮立即消失。
2. 在 390×844 自由辩论中同时制造举手队列和未完成文字草稿，确认 CTA、队列和底栏互不遮挡。
3. 等待真人固定发言阶段至少 10 秒，确认完整时间不变；点击开始后才递减。
4. 完成比赛后检查长篇文字记录在桌面和手机上的可读性。
