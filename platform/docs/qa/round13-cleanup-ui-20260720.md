# Round 13 非音频前端与代码清理审计

日期：2026-07-20

## 结论

本轮只审计和修改赛事大厅、赛事详情、房间大厅、个人中心及共享的非音频前端基础设施。实时辩论舞台、浏览器播放、AudioWorklet、PCM、LiveKit、MOSS/TTS 和可靠音频基线均未修改。

现有产品主线已经稳定为“赛事 → 房间 → 比赛 → 结果/历史”，运行页面中没有教师、课堂、课程、班级、全班或教学活动文案。页面整体视觉不是通用后台模板：正反双方色带、房间号、席位状态和“辩”字识别符都来自辩论场景；交互密度和反馈方式接近成熟竞赛产品。现阶段不应为了模仿某一家公司的外观而重做全局配色，优先保持学生在高频比赛中的识别速度和操作稳定性。

本轮修复了三个确定问题：

1. 导航、房间页和参赛弹窗同时挂载时，会各自请求一次 `/api/auth/session-state`。现在同一时刻的会话读取和登录态变更刷新会合并为一次请求，避免重复网络、Cookie 校验和组件抖动。
2. 赛事大厅、赛事详情、排行榜、房间大厅和个人中心原先只有一行居中文字作为加载态。现在使用统一的轻量加载卡片，具有 `role=status`、`aria-live`、`aria-busy` 和减少动态效果兼容；视觉只使用已有品牌令牌，没有引入新依赖或扩大首屏包。
3. 个人中心移动端的恢复席位按钮曾由两段重复 CSS 同时赋予 `width:100%` 和 `margin-left:10px`，可能在窄屏向右溢出。重复规则已合并并移除外扩。旧系统导入且没有胜负数据的已完成比赛也不再显示“待复核”，而是准确显示“结果未记录”。

## React / Next.js 性能审计

- 首页的赛事、公开房间和排行榜请求已经并行发起，次要面板慢或失败不会形成首要 CTA 的瀑布。
- 后台大型模块使用 `next/dynamic`，只有进入对应模块时才下载和取数。
- 赛事详情和个人中心使用请求序号拒绝迟到响应，分页或路由快速切换不会被旧请求覆盖。
- 房间大厅的写操作使用幂等键，并允许 WebSocket 快照确认“服务端已提交但 HTTP 响应丢失”的操作。
- 新增会话请求合并后，两个并发 `useSession` 消费者的单次加载只发出 1 个请求；登录态变更时多个消费者同样只发出 1 个刷新请求。
- 没有新增第三方组件、字体、图片或客户端状态库；加载态仅增加少量静态 JSX/CSS。

## 无关代码与历史残留

对 `apps/web/app`、`apps/web/components` 和 `apps/web/lib` 的 50 个运行时 TypeScript 文件执行检索：

- 教师、老师、课堂、课程、班级、全班、教学活动及对应英文词命中为 0。
- 教师/课堂词汇仍出现在 E2E 的退役路由反向测试中；该测试用于确保 `/teacher`、`/teacher/consents`、`/admin/classrooms` 持续返回 404，不应删除。
- 对非测试组件和库执行运行引用检查，没有发现可证明无引用的 Web 源文件，因此本轮没有为了“看起来更干净”而冒险删除业务代码。
- `LightTTS`、`CosyVoice` 等历史内容仍存在于事故复盘、迁移验证器和音频质量脚本中。其中部分被 README、测试或生产 MOSS-only 防回退门直接引用；并且用户明确冻结语音链路。本轮只把它们登记为后续独立清理窗口的债务，不删除、不改名、不移动。
- `.DS_Store` 已被根目录和 平台 `.gitignore` 排除，不会进入 GitHub 分支或新服务器恢复集，也不是生产备份。

## 后续建议

1. 用真实匿名、普通参赛者、房主和管理员四种身份持续做 390×844、1366×768、1920×1080 浏览器回归；以操作完成时间、错误恢复成功率和横向溢出为门禁，而不是只做截图评审。
2. 只有在独立音频变更窗口、可靠版本可即时回滚且完整语音门禁可运行时，才处理历史 TTS 脚本和文档；不要把普通代码清理与语音运行时清理混在一次发布中。
3. 若赛事或用户规模继续增长，再将首页公开房间与榜单改为带服务端初始数据的渐进增强；当前 API 延迟和页面局部失败隔离尚不需要引入额外缓存框架。
