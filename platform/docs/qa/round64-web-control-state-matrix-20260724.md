# Round 64：Web 比赛控制状态矩阵审计

日期：2026-07-24  
范围：赛前大厅、辩手比赛舞台、单场比赛控制台。  
约束：只修改 Web 与 Web 测试；未修改 API、音频库，未部署。

## 审计目标

以真实 4v4 比赛顺序检查操作是否符合现场心智：

`进入大厅 → 绑定设备 → 选择席位 → 准备 → 房主开始 → 开场准备 → 真人发言 → AI 生成/合成 → AI 播放 → 自由辩论 → 断线等待 → 自动暂停 → 恢复/重试 → 跳过/终止 → 比赛结束`

每个状态重点检查：

- 是否只显示当前真正有意义的操作。
- 危险操作是否需要确认。
- 禁用按钮是否有准确、可读的原因。
- 是否会误导用户重复开始、错误接管、掩盖故障或丢失未提交文字。
- 房主身份是否在比赛开始后保持稳定。

## 修复结果

### 1. 运行中不再提供房主移交

问题：控制台在比赛运行中仍显示“移交房主”，会破坏已确定的恢复责任人，并与“运行中房主身份稳定”规则冲突。

修复：从比赛控制台完全移除运行中、暂停中和终态的房主移交入口及请求逻辑。比赛开始后只能由原房主或系统管理员恢复。

### 2. 服务异常和断线暂停不能通过“跳过”掩盖

问题：服务异常暂停，或真人断线自动暂停后，控制台仍可能允许跳过当前阶段。该操作会把异常误当作正常赛程选择，并可能丢弃本应重试或恢复的环节。

修复：

- 服务异常暂停：跳过禁用，提示先重试当前步骤。
- 真人断线暂停：跳过禁用，提示先恢复比赛。
- 服务异常并伴随真人断线：先等待全部真人重新连接，再重试。
- 普通运行状态和无异常的人工暂停仍保留显式跳过能力，并继续要求二次确认。

### 3. 比赛舞台阻止危险的异常重试

问题：舞台的异常提示条此前没有识别“服务异常 + 真人断线”组合，房主仍可直接点击重试；本页存在尚未提交的真人文字时，也缺少清晰的禁用原因。

修复：

- 有真人仍断线时，异常重试按钮显示“等待真人重连”并禁用。
- 本页仍有录音、识别整理或待提交文字时，重试、暂停和提前结束提供明确原因，避免覆盖或遗失本地内容。
- 快捷暂停按钮的无障碍名称和悬停说明现在直接描述真实阻塞原因，不再出现“按钮写暂停、实际却因本地文字被禁用”的矛盾。

### 4. 区分 AI 准备和 AI 播放

问题：Agent 内容生成、语音合成和浏览器实际播放此前统一显示为“AI 正在发言”，导致房主可能在正常合成期间误点重置。

修复：

- 生成或语音合成阶段：显示“AI 发言正在生成或合成语音”，操作命名为“重试 AI 语音准备”，并明确只有长时间无进展时使用。
- 音频播放阶段：显示“AI 语音正在播放”，异常操作保持“重置当前发言”。
- 两种状态的确认说明分别描述实际影响。

### 5. 大厅设备绑定不再闪现失败状态

问题：首次进入大厅时，设备控制请求尚未返回，页面会先按失败状态展示，造成“刚打开就报错”的错误感知。

修复：

- `acquiring`：展示“正在绑定当前设备”，说明绑定完成前不会提交准备或开赛。
- `unavailable`：只在真实请求失败后展示“设备绑定暂时失败”和重试按钮。
- `lost`：只在真实跨设备控制冲突时展示接管说明。

## 4v4 状态矩阵

| 场景 | 主要操作 | 恢复/危险操作 | 结果 |
| --- | --- | --- | --- |
| 大厅首次绑定 | 等待绑定 | 无接管按钮 | 不误报失败 |
| 真人未准备/离线 | 准备或等待 | 开始禁用并列出人员 | 不会强行开赛 |
| 开场准备 | 比赛准备中 | 跳过禁用；可紧急终止 | 不重复开始、不提前计时 |
| 等待真人发言 | 当前辩手开始发言 | 房主可暂停/跳过 | 轮次权限由服务端状态呈现 |
| 真人发言中 | 辩手结束并提交 | 跳过禁用；仅可紧急安全暂停 | 不丢弃进行中发言 |
| AI 生成/合成 | 自动等待 | 长时间卡住才可重试准备 | 不把正常准备误判为播放故障 |
| AI 播放 | 自动推进 | 卡顿或提前结束时可重置 | 不切换播放器或辩手 |
| 自由辩论 | 当前阵营按轮次发言 | 常规暂停、显式跳过 | 保留单轮与总时钟语义 |
| 断线 60 秒内 | 等待人员返回 | 不跳过；可人工暂停 | 真人席位不变 |
| 断线超时暂停 | 等待全部真人连接 | 继续禁用，终止仍可用 | 无 AI 接替、无房主转移 |
| 服务异常暂停 | 重试当前步骤 | 跳过禁用 | 不掩盖异常 |
| 服务异常且有人断线 | 先等待人员 | 重试和跳过均禁用 | 恢复顺序明确 |
| 本页有未提交文字 | 先提交或清除 | 暂停、终止给出阻塞原因 | 防止本地内容丢失 |
| 比赛终态 | 查看记录/结果 | 所有控制禁用 | 不显示无效移交动作 |

新增或调整覆盖：

- 比赛开始后不显示房主移交。
- 服务异常暂停时跳过禁用且原因可访问。
- AI 合成和 AI 播放采用不同说明及操作名称。
- 大厅首次设备绑定保持中性等待状态。
- 服务异常并伴随真人断线时，舞台重试必须等待人员返回。
- 终态只保留准确的禁用控制，不依赖无效房主移交按钮。
