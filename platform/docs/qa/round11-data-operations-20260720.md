## 生产数据不变量

在 PostgreSQL 权威数据上检查所有活动和终局房间，结果如下：

- 终局房间中的活动 Speech：0。
- 停用账号的有效 Session：0。
- 活动房间中仍由停用账号占用的真人席位：0。
- 活动房间中的停用房主：0。
- 同一用户同时占用多个活动房间：0。
- 席位用户与设备控制 Session 用户不一致：0。
- `Room.seq` 与该房间最大事件序号不一致：0。
- Match 与 Room 的终局状态组合一致；唯一非终局组合是一个真实用户主动暂停的 `running / paused` 房间，没有擅自终止。

发现两个 7 月 17 日旧 QA 账号仍有物化 `LeaderboardEntry`。公开接口已经过滤测试账号，不会向学生展示，但后台聚合表仍包含旧版本留下的两行。使用权威比赛、裁判结果和 `Room.is_test_data` 重新构建现有排行榜分组后：

```text
groups=1, before=2, after=0
测试或停用账号物化榜单行=0
```

追加式 `RatingChange` 没有删除，仍可用于审计历史；后续房间/账号重新分类已经由 Round 10 管理接口自动触发同一重建逻辑。

## 公共读取性能

从公网以 50 个 keep-alive 并发请求公开只读接口，每个接口 200 次：

| 接口 | 状态 | 平均延迟 | p95 | p99 |
| --- | --- | ---: | ---: | ---: |
| `/` | 200/200 | 164ms | 449ms | 580ms |
| `/api/competitions` | 200/200 | 180ms | 376ms | 397ms |
| `/api/live-rooms` | 200/200 | 287ms | 669ms | 718ms |

排行榜在数据重建结束后的第一次压测出现一次 p95 约 5 秒峰值。没有据此直接加入缓存；连续五轮、每轮 100 请求复测为：

```text
平均延迟：210 / 252 / 253 / 255 / 257ms
p95：417 / 551 / 546 / 553 / 561ms
```

证据更符合数据重建后的短时 PostgreSQL 争用，而不是稳定查询瓶颈。为了避免排行榜在赛果更新后出现数秒陈旧，本轮不引入进程内 TTL 缓存。运维上应避免在上课或大规模开赛高峰执行全量排行榜重建，并在重建后再跑公开接口门禁。

## 运行日志

当前 API、Engine、Worker 和 Web 日志没有 Round 10 部署后的新异常。历史日志中存在两类已经纳入本轮验证的旧记录：

- WebSocket 接受连接后尝试发送 HTTP denial response；Round 11 新增隐藏大厅 accept 后关闭测试，当前路径只发送 4401/4403 close。
- 流式 Agent 生成器取消同拍可能出现 `Task exception was never retrieved`。最小复现位于 Round 11 引擎测试；修复点属于冻结的实时语音 pipeline，本轮遵守音频保护要求未修改。

## 成熟开源实现对照

通过 GitHub 代码检索对照了以下当前活跃项目：

- [Colyseus](https://github.com/colyseus/colyseus)：恢复成功后清除 reserved seat/reconnection 状态；关停时先完成离线清理再缓存房间，避免恢复陈旧席位。
- [boardgame.io](https://github.com/boardgameio/boardgame.io)：每次状态更新后重新检查 turn/phase/game 结束条件，终局不是只在计时器分支检查。
- [Lichess](https://github.com/lichess-org/lila)：连接状态、断线宽限和比赛计时分开维护，断线恢复不是由客户端单方面决定。

当前平台的服务端权威席位、追加式事件、恢复申请、终局写保护和引擎重启清理与上述原则一致。本轮新增测试重点放在“跳过后迟到 Agent”“真人提交与终止同拍”“停用账号席位清理”和“隐藏大厅 WebSocket”这些等价风险上，没有复制第三方代码。

## 无用代码审计

- `npx knip` 未发现未使用的前端文件、导出或依赖。
- `vulture --min-confidence 90` 只报告冻结 LightTTS Redis Lua 脚本的两个参数名；它们是 Redis `EVAL` 调用签名，不是可删除业务代码。
- 旧课堂表的 Alembic 创建/删除迁移仍是从历史数据库升级到当前 schema 的必要链路，不能为了目录整洁删除。
- 录音同意兼容组件仍被冻结 DebateStage 静态引用；当前后端已不再返回该字段。移除它需要修改受保护舞台文件，应等独立音频变更窗口统一处理，而不是在本轮冒险拆除。
