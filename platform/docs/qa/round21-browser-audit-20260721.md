## 结论

公开产品闭环已经具备可用基础：页面加载快、视觉统一、移动端没有横向溢出，公开 API、RTC Token 和 LiveKit 连接均成功，浏览器控制台未发现 JavaScript 异常或失败请求。匿名观众页面没有文字稿入口，公开房间数据也没有 `transcript` 或发言正文。

本轮发现 5 项产品问题，其中 3 项中等、2 项较低。唯一直接修改的是排行榜名次的可读性；其余涉及观战舞台冻结基线或需要统一产品决策，先保留为后续工作。

## 已验证通过

- 首页、赛事详情、排行榜、登录、注册、公开观战和错误房间页面均能通过 HTTPS 正常加载。
- 连续访问四个核心页面共观察到 115 个网络请求，没有 4xx/5xx；核心 API 均返回 200。
- 公开观战成功获取房间快照、RTC Token 并连接 LiveKit；离开页面后连接正常断开。
- 匿名访问 `/me` 会跳转到 `/login?next=/me`，匿名访问 `/admin` 不会显示管理内容。
- 无效房间号有明确错误页；输入框会过滤非数字，只有六位房间号才允许提交。
- 登录和注册字段具有正确 label、`required` 与 password-manager `autocomplete` 属性。
- 注册密码不一致会即时显示 `role=alert`，错误登录显示统一且不泄露账号存在性的提示。
- 赛事详情使用标准 ARIA tabs，键盘 `ArrowRight` 能移动并切换选项卡。
- 参赛弹窗具有 `role=dialog`、`aria-modal=true`、标题关联、初始焦点、Escape 关闭和焦点归还。
- 首页跳转链接可通过键盘聚焦，激活后焦点正确落到 `main#main-content`。
- 390px 宽度下首页、赛事详情、排行榜和观战舞台无横向溢出。
- 所有匿名观众不可见文字稿：观战页没有相关按钮；`GET /api/rooms/117519` 不含 `transcript` / `speech_content`，当时 `speeches` 为空。

## 问题

### B21-01：前三名只有奖牌图标，名次对读屏器不可见

| 字段 | 内容 |
| --- | --- |
| 严重度 | Medium |
| 类别 | Accessibility / Content |
| 页面 | `/rankings` |
| 状态 | **已在本地修复并增加单元测试，尚待随主版本发布** |

桌面和移动排行榜的前三名只显示不同颜色的奖牌 SVG。生产可访问性树中首行“排名”单元格没有名称，视觉用户也只能通过金银铜颜色推断具体名次。颜色和装饰图标不应成为名次的唯一表达。

修复后奖牌标为 `aria-hidden`，并同时展示 `#1`、`#2`、`#3` 文本。

证据：[桌面排行榜](round21-browser-audit-evidence/screenshots/rankings-desktop.png)、[移动排行榜](round21-browser-audit-evidence/screenshots/rankings-mobile-390.png)

### B21-02：匿名观众的“观看设置”没有设置项，并显示“麦克风：待机”

| 字段 | 内容 |
| --- | --- |
| 严重度 | Medium |
| 类别 | UX / Content |
| 页面 | `/rooms/117519/watch` |
| 状态 | 待处理；所在舞台属于冻结音频/播放基线，本轮未修改 |

“设置”按钮打开的窗口只有 AI 语音状态、麦克风状态和服务端计时说明，没有任何可调整选项。匿名观众没有麦克风发布能力，但窗口写着“麦克风：待机”，容易让学生误以为网站正在等待或准备使用其麦克风。

建议二选一：

1. 改名为“连接状态”，明确显示“观战模式不使用麦克风”；或
2. 保留“观看设置”，提供字幕、字号、减少动画、音量等真正的观看选项，并把麦克风信息移除。

证据：[观看设置窗口](round21-browser-audit-evidence/screenshots/watch-empty-settings.png)

### B21-03：手机观战页截断核心辩题，且没有展开方式

| 字段 | 内容 |
| --- | --- |
| 严重度 | Medium |
| 类别 | Responsive / UX |
| 页面 | `/rooms/117519/watch`（390×844） |
| 状态 | 待处理；所在舞台属于冻结音频/播放基线，本轮未修改 |

手机顶部只显示单行省略的辩题，例如“AI 的迅猛发展提升了还是降低了人类创作者存在的…”。辩题是理解比赛的核心信息，但页面没有点击展开、长按提示或其它完整展示入口。

建议允许题目最多两行，并支持点击顶部题目打开只读详情层；该层不能遮挡计时和发言控制。

证据：[390×844 观战页](round21-browser-audit-evidence/screenshots/watch-mobile-390x844-v2.png)

### B21-04：所有页面使用相同浏览器标题

| 字段 | 内容 |
| --- | --- |
| 严重度 | Low |
| 类别 | Accessibility / Navigation / SEO |
| 页面 | 首页、赛事详情、排行榜、登录、注册、观战 |
| 状态 | 待处理 |

实测所有页面标题均为“稷下辩论｜AI 时代的辩论竞技场”。多标签浏览、浏览器历史、读屏器页面切换和分享收藏时无法区分页面。

建议使用统一模板，例如：

- `赛季排行榜｜稷下辩论`
- `4v4 人机辩论正式赛｜稷下辩论`
- `观战 #117519｜稷下辩论`
- `登录｜稷下辩论`

### B21-05：注册前没有展示密码规则

| 字段 | 内容 |
| --- | --- |
| 严重度 | Low |
| 类别 | Form UX |
| 页面 | `/register` |
| 状态 | 待处理 |

密码最少 8 位的要求只有在用户填写并提交短密码后，才由浏览器原生校验显示。表单正常状态没有规则提示，也没有密码可见性切换。学生容易完成所有字段后才发现规则，移动端尤其增加返工。

建议在密码框下始终显示“至少 8 个字符”，输入时用非阻断状态提示是否满足；确认密码继续保留即时一致性校验。

证据：[注册页](round21-browser-audit-evidence/screenshots/register-desktop.png)

## 未覆盖范围与下一轮建议

本轮没有使用生产用户凭据，也没有向生产数据库写入 QA 用户，因此未检查登录后的个人中心、建房、抢座、准备、房主控制台和真实人类发言流程。这些流程应在隔离测试赛事或专用 QA 账号下进行，避免污染排行榜和历史数据。

下一轮优先级：

1. 用至少 4 个隔离账号执行 1v1、4v4 的认领席位、准备、刷新、断线、设备接管测试。
2. 在不改动可靠音频基线的前提下，补测弱网、后台切前台、蓝牙耳机切换和 20 名观众边界。
3. 为观战页增加真实用户性能监控，记录 RTC 连接耗时、首字幕、首声音、重连和卡顿指标。
4. 将页面标题、密码规则和观战角色文案纳入 UI 回归测试。
