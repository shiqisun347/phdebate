# Round 62：房间与比赛控制逻辑专项

日期：2026-07-24  
范围：赛前大厅、房主控制台，以及与两者直接相关的前端测试。  
部署状态：仅完成本地实现与验证，未部署生产环境。

## 结论

本轮修复了两个会直接破坏完整比赛流程的控制漏洞，并收敛了普通辩手和房主在页面中看到的操作。

1. 真人已经点过准备、但当前实际离线时，房主页面过去仍允许点击开始。现在页面会明确列出离线姓名和席位，禁止开始，避免开局后立即进入断线等待或自动暂停。
2. 服务异常与真人断线同时发生时，控制台过去仍会启用“重试当前步骤”和“跳过当前阶段”，但服务端必然拒绝。现在必须先等全部真人重新连接，之后才开放重试。
3. 已准备的普通辩手不再看到一个无作用的“已准备，等待房主”禁用按钮。底部固定操作改为“取消准备”，席位退出仍保留在本人操作区；房间设置、移出其他人、开始和关闭房间仍只对房主显示。
4. 房主控制台新增“自动流程当前步骤”，会区分语音准备、等待真人开始发言、真人发言提交、AI 发言播放、自动评审、人工暂停、断线暂停和服务异常，减少不知道系统为何等待的情况。
5. 断线倒计时文案已纠正：60 秒内返回不需要房主手动操作；只有超时并自动暂停后，才需要房主确认人员齐全并继续。

## 操作边界

### 普通辩手

- 未入席：选择空席。
- 已入席但未准备：底部确认准备。
- 已准备：底部取消准备；需要彻底离开时使用“退出当前席位”。
- 不显示房主的开始、移出他人、关闭房间、暂停、跳过、重试或终止操作。

### 房主

- 所有真人必须在线且准备完成，才开放开始比赛。
- 开始后正常流程自动推进，底部只保留当前最必要的主操作。
- 真人正在发言时，暂停和跳过保持禁用，并说明需先结束和提交发言。
- 纯断线暂停：全部真人重连后使用继续比赛。
- 服务异常暂停：使用重试当前步骤。
- 服务异常叠加断线：先等待全部真人重连，再使用重试当前步骤。
- 跳过和提前结束继续放在异常处理、危险操作区域，并要求确认。

## 仍需主线补齐的服务端边界

前端现在会阻止离线真人参与开赛，但当前 `POST /api/rooms/{code}/start` 仍只校验真人 `is_ready`，没有校验 `connected`。因此直接请求接口或使用陈旧页面仍可能绕过前端。

正式发布前应在服务端开始事务中再次拒绝离线真人，并增加 API 回归测试。前端校验只能用于即时反馈，不能代替服务端权威校验。
