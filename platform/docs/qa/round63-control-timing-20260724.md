# Round 63：比赛控制与计时流程审计

日期：2026-07-24  
范围：单场比赛优先；房主控制、真人发言、断线恢复、阶段跳过、1v1/4v4 自动流程、同设备大厅进入比赛页的控制权绑定。  
部署：未部署。

## 结论

本轮修复了四类会直接破坏完整比赛的问题：

1. 控制台原先可在真人正在发言时直接跳过阶段，导致该次发言被中断。现在服务端拒绝此操作，必须正常结束发言，或由房主执行“紧急暂停当前发言”。
2. 真人刚断线、尚未满 60 秒时，房主此前仍可通过继续、重试或跳过绕过恢复等待。现在真人不可用期间均禁止推进；满 60 秒后只安全暂停，不进行 AI 接替、席位转移或房主转移。
3. 控制台缺少明确的真人发言应急操作。现在提供“紧急暂停当前发言”，保留已确认文字和剩余时间；恢复后仍由原辩手重新开始发言。
4. 同一浏览器从赛前大厅进入辩论页时，短暂数据库锁冲突会被错误显示为“其他设备已接管”。现在仅真实 lease 冲突显示接管；房间繁忙、数据库临时不可用和网络瞬断只做有限自动重试，绝不会自动强制接管。

运行中或暂停中的房主身份保持稳定。只有赛前大厅允许处理离线房主；比赛开始后，原房主或系统管理员负责恢复。

## 风险与后续验证

- SQLite 测试中的全局写锁比正式 PostgreSQL 更容易放大竞争；本轮前端修复不依赖数据库类型，正式环境的 `55P03` 和应用锁超时均会被识别为临时繁忙。
- 尚未在生产 PostgreSQL、真实 WebSocket/LiveKit 和多浏览器设备上执行现场回归，也未部署。
- 整合后必须复测以下真实路径：
  1. 同一浏览器：创建房间 → 准备 → 开始 → 自动进入辩论页，不出现接管提示。
  2. 两台真实设备登录同一账号：第二台未经确认不能取得席位；确认接管后第一台立即只读。
  3. 真人发言中断网：60 秒内保留席位和比赛；满 60 秒自动暂停；无 AI、无房主或席位自动转移。
  4. 1v1 与 4v4 各完成一场，覆盖准备、倒计时、固定阶段、自由辩论、总结和结果页。
