# Round 44 生产完整比赛验证（2026-07-22）

> 本文是一次性 QA 证据，不是规范性产品文档。产品规则以 `docs/official/system.html` 和 `docs/official/user.html` 为准。

## 场景

- 生产地址：`https://117.50.192.216`
- 房间：`737582`（已标记为测试数据）
- 赛事：1v1 辩论训练赛
- 辩题：人工智能时代是否仍需学习编程
- 席位：正方真人测试账号、反方 AI；测试账号没有建立房间 WebSocket，用于验证断线边界
- 语音链路：MOSS-Realtime → LiveKit → 单条 WebRTC 音轨；不保存比赛音频文件

## 完整流程结果

房间从创建、准备、开赛、主持提示、双方立论、自由辩论、双方总结、自动裁判一直推进到 `completed`。共形成 8 段有效发言，裁判事件正常写入，最终产生 `match.completed`，过程中没有服务异常暂停、TTS 失败或裁判失败。

抽样的 Agent 首个可读文本到服务端首个音频帧耗时为 `1.241–1.471 秒`，均低于 3 秒目标。每次发言继续使用相同的 LiveKit TTS 发布音轨，没有启用浏览器替代播放器。

## 暴露的 P0 规则问题

当时生产 API 尚未包含“开赛时重建断线宽限时钟”的本地修复。真人测试席位在房间创建时就被记录为离线，开赛后约 12 秒被旧逻辑转换为 `ai_substitute`，随后由 AI 完成正方发言。

用户随后明确调整产品规则：

1. 不允许系统把真人席位自动转换为 AI。
2. 真人连续离线达到 60 秒时，冻结当前阶段和自由辩论计时，并自动安全暂停整场比赛。
3. 保留真人席位、用户 ID、房主身份和历史记录；用户重新连接后，由房主或管理员显式继续比赛。
4. 未重新连接的真人仍存在时，服务端拒绝恢复比赛。

因此，本次完整比赛证明 Agent、TTS、主持提示、自由辩论、总结和裁判主链能够闭环，但旧的断线接替行为不再符合当前产品规则。后续生产验收必须使用新的“60 秒断线暂停”实现重新执行真人场景。
