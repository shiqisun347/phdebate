# Round 11 前端体验与性能审计

日期：2026-07-20

范围：赛事大厅、4v4 房间大厅、系统管理后台，以及这些页面的响应式、可访问性和客户端请求行为。实时辩论舞台、LiveKit、AudioWorklet、PCM、MOSS/TTS 与浏览器连续播放路径均不在本轮修改范围内。

## 设计判断

本平台服务于大量学生自主组局和参加人机辩论。非比赛舞台页面的首要任务不是营造课堂氛围，而是让用户快速辨认赛事、阵营、席位、状态和下一步操作。

本轮采用更接近成熟大型产品后台的设计约束：降低无意义的光晕和大圆角，提高边界与信息密度；正反双方只在真正表达阵营时使用蓝、红双色；保持主操作突出，其余界面安静。赛事卡片顶部的正反双色“辩论轨道”作为平台特有视觉标记，而不是继续堆叠通用紫色渐变装饰。

## 发现与修复

### 1. 4v4 八席在真实人数下缺少团队概览

此前大厅虽然能显示八席，但团队标题只有“正方 / 反方”，席位辅助文字仅 10px。学生需要逐行数席位，平板和普通笔记本上也不易快速判断真人数量。

已修复：

- 正反方分别形成有边界的席位组，避免八个席位在视觉上混成一列。
- 团队标题直接显示“真人数 / 总席位数”。
- 席位最小高度从 66px 提升到 72px，状态文字提升到 11px 并改善行高。
- 文本列使用 `minmax(0, 1fr)` 和强制换行，较长真实姓名不会挤坏状态图标。
- 为正方、反方席位组增加明确的可访问名称。

验证新增完整八席数据：正反方各 4 席、真人和空席混合，所有席位均可被辅助技术识别，并通过 axe 自动检查。

### 2. 管理员刷新页面会丢失正在工作的模块

此前管理员在比赛监管、用户管理或审计日志中处理问题时，刷新页面会返回系统总览。链接也无法指向具体管理模块，故障排查和多人协作成本偏高。

已修复：

- 当前模块写入 `?module=rooms|users|competitions|...`，保留地址中其他查询参数与 hash。
- 直接打开或刷新模块链接后，先验证管理员并加载总览，再只加载目标模块；不会预取全部后台数据。
- 同一个模块的并发加载仍使用已有 Promise 去重机制。
- 非法模块参数安全回退到系统总览。
- 桌面端管理模块支持上/下方向键以及 Home/End 快速切换，采用 roving `tabIndex`，减少键盘用户重复 Tab。

### 3. 通用卡片视觉过于模板化

原卡片使用较强紫色光晕、22px 圆角和较重阴影，容易呈现通用 AI 产品模板感，也降低赛事后台的信息密度。

已调整：

- 普通卡片与面板改为更克制的深蓝实底、18px 圆角和更轻的阴影。
- 赛事卡片增加正反双色顶轨，颜色只编码辩论双方，不作为无意义装饰。
- 后台当前模块改用低饱和蓝底和左侧定位条，长列表下更容易保持方位感。

## 性能审计结论

- 首页赛事、公开比赛和排行榜请求已并发启动，不存在首屏串行瀑布。
- 排行榜页和后台独立数据请求已使用 `Promise.all`。
- 后台非首屏模块已使用 `next/dynamic` 拆包，并按首次访问懒加载。
- 后台房间、用户和审计数据均为服务端分页，每页 100 条，并有请求序列保护，旧请求不会覆盖新筛选结果。
- 管理模块新增加载恢复通过 ref 调用当前 handler，未引入 effect 依赖抖动或重复请求。
- 比赛结果长逐字稿和时间线已有 `content-visibility: auto`；本轮未触碰其中音频元素和播放行为。
- 未发现值得以额外依赖或复杂缓存换取的性能问题；因此没有引入 SWR、全局状态库或虚拟列表。

## 生产弱网问题跟进

生产黑盒测试复现了一个 Medium 问题：离线认领席位失败后，WebSocket 已经显示“实时连接”，大厅仍保留“网络连接失败，本次操作可能尚未提交”的旧提示。

修复方式：

- `useRoom` 将 WebSocket 连接错误和 REST 权威快照错误拆成 `connectionError`、`snapshotError`，两者分别建立和清除；兼容字段 `error` 仍返回当前最重要的房间错误。
- 大厅将普通请求错误与 `status=0` 的未确认写入分开。恢复联网后不再谎称网络仍断开，而是明确提示“连接已恢复、上次操作结果未确认”，并说明使用原幂等请求编号安全重试。
- 后续操作成功时清除未确认提示；若权威房间快照已经证明认领、准备、释放、开始、关闭或移出操作成功，也会自动清除。
- 覆盖“WebSocket 先确认写入、失败的 fetch 后返回”这一乱序竞态，避免页面重新显示已经过期的失败警告。
- 用户可在理解未确认状态后主动关闭提示；未确认写入不会被静默当作成功。

跟进验证：

- 大厅与 `useRoom` 针对性测试：33 项通过。
- Web 全量测试更新为 258 项通过。
- TypeScript、ESLint（0 error）通过。
- 可靠音频基线仍为 82 个文件，指纹未变化。

## Skip link 键盘焦点跟进

生产浏览器测试发现全局“跳到主要内容”链接只能滚动到 `#main-content`，激活后的焦点仍停留在 `BODY`，键盘用户下一次 Tab 仍需重复经过导航。

已修复：

- `main` 增加 `tabIndex=-1`，允许程序聚焦但不会进入普通 Tab 顺序。
- skip link 保留原生 `href="#main-content"` 行为，不取消默认事件，因此 URL hash、浏览器历史和原生滚动不受破坏。
- 原生 fragment 导航完成后的下一帧将焦点移到 `main`，并使用 `preventScroll` 避免二次跳动。
- Ctrl、Command、Shift 或 Alt 等修饰点击不被脚本接管。

验证：

- 新增 2 项 skip link 测试，覆盖焦点转移、`defaultPrevented=false`、`tabIndex=-1` 和修饰点击。
- Web 全量测试更新为 260 项通过，37 个测试文件全部通过。
- TypeScript、ESLint（0 error）通过。
- 可靠音频基线仍为 82 个文件，指纹未变化。
