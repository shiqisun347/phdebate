# Round 22 真人比赛恢复能力审计

日期：2026-07-21  
范围：多人类 / 多 Agent 比赛中的页面误关、网络掉线、跨设备接管、AI 临时代替、真人回归、房主与管理员应急处理。  
排除范围：TTS、ASR、浏览器音频播放和所有可靠语音冻结路径。本轮未部署。

## 结论

系统已有完整的服务端权威恢复主链路，并非只依赖前端按钮：

- 同一登录会话刷新或误关页面后，允许自动更换设备租约并恢复控制；旧租约立即失效。
- 不同登录设备接管同一席位时，需要用户明确确认；另一设备正在发言时禁止强制接管。
- 真人断线后保留席位 60 秒；超时由 AI 接替，遗留真人发言被中断，不会形成僵尸发言。
- 原辩手返回观战页后可申请恢复；必须已重新连接、当前无发言、账号有效、且未在其他房间占用真人席位。
- 房主掉线或主动退出时，控制权优先移交给其他在线真人；没有在线真人时仍保留系统管理员修复入口。
- 房主和系统管理员可以暂停、恢复、重试失败步骤、跳过异常阶段和终止比赛；所有写操作仍由后端校验状态和权限。
- `/me` 提供进行中比赛返回入口，并显示 AI 接替、恢复申请等待审批和暂停状态。

本轮发现并修复 3 个高置信度产品缺口。

## 本轮修复

### 1. 管理员“直接恢复真人”从隐藏接口变为可用产品功能

后端原本已有 `POST /api/admin/rooms/:code/seats/:seatKey/restore`，但任何管理页面都没有入口。管理员面对已返回但尚未提交申请的学生，只能等待学生理解申请流程，无法快速排障。

现在房间控制台会对系统管理员显示“直接恢复真人”：

- 仅服务端投影 `can_admin_restore=true` 时显示，普通房主不会看到无权限按钮。
- 原辩手未连接时显示“等待辩手连接”。
- 房间内仍有发言时显示“发言结束后恢复”。
- 操作前确认姓名，成功后立即合并 REST 权威快照并显示反馈。
- 后端继续复核管理员角色、房间状态、连接状态、发言冲突、账号状态和跨房间真人席位冲突。

### 2. AI 接替参赛者在终态可以回到自己的比赛结果

此前，被 AI 接替的参赛者会从 `/debate` 转到 `/watch`；若比赛随后进入 `review_required` 或 `terminated`，观战页会一直停留在终止舞台，无法自然进入结果/历史页面。

现在：

- 已完成比赛仍对所有观战者跳转公开结果。
- `review_required` / `terminated` 只对原参赛者或房间控制者跳转结果。
- 普通匿名观众仍停留在脱敏观战投影，不会因此获得未发布结果。

### 3. 跳过阶段增加防误触确认

“跳过当前阶段”会立即推进状态机，原先单击即执行。现在确认框会包含当前阶段名称并明确提示不可撤销；取消时不会发出 REST 请求。真人发言中仍由前后端共同禁止跳过。

## 恢复能力矩阵

| 场景 | 用户可见措施 | 服务端保护 | 当前状态 |
|---|---|---|---|
| 页面刷新 / 误关后返回 | `/me` 继续比赛；同会话自动恢复 | 新租约替代旧租约，旧设备写入被拒绝 | 已覆盖 |
| 网络短暂掉线 | WebSocket 自动退避重连；REST 应急控制仍可用 | 房间快照按 `seq` 合并，避免旧事件覆盖新状态 | 已覆盖 |
| 新设备接管 | 明确“确认接管到当前设备” | 发言中禁止跨会话接管；强制接管写审计事件 | 已覆盖 |
| 掉线超过 60 秒 | AI 接替，原用户转只读观战 | 中断遗留真人发言、清空控制租约 | 已覆盖 |
| 真人希望回来 | 观战页和 `/me` 可提交/撤销恢复申请 | 连接、发言、账号和跨房间冲突校验 | 已覆盖 |
| 管理员现场恢复 | 控制台“直接恢复真人” | 管理员角色与完整状态复核 | 本轮补齐 |
| 房主临时离开 | 主动移交；也可让 AI 接替自己 | 自动优先移交给在线真人 | 已覆盖 |
| 外部服务失败 | 控制台显示失败原因并“重试异常步骤” | 失败发言标记、幂等操作、状态机恢复 | 已覆盖 |
| 人工暂停 | “恢复比赛” | 非暂停状态拒绝恢复 | 已覆盖 |
| 错误阶段 | 确认后跳过 | 真人发言中拒绝；后端复核房间状态 | 本轮加固 |
| 无法继续 | 确认终止 | 中断活跃发言和裁判任务，归档为 terminated | 已覆盖 |
| AI 接替后比赛结束 | 原参赛者进入结果页 | 未发布结果仍不向普通观众开放 | 本轮补齐 |
