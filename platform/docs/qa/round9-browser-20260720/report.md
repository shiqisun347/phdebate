# Round 9 生产黑盒深度 QA

日期：2026-07-20
环境：`https://117.50.192.216`

## 范围

使用四个隔离的 agent-browser 会话，模拟三名登录参赛者和一名匿名观众。没有启动比赛、
没有使用麦克风，也没有调用 Agent、TTS 或浏览器音频播放。

## 已验证流程

1. 注册页能拒绝两次密码不一致，并保留账号和真实姓名输入。
2. 房主创建 1v1 自定义辩题房间 `671366`；第二名用户认领反方席位并准备、取消准备。
3. 第二名用户关闭并重新进入页面后，席位仍由服务端保留；新设备必须显式确认接管，旧控制
   lease 没有被静默复用。
4. 第二名用户主动释放席位后，第三名用户可以认领并准备；房主准备后，“锁定席位并开始”
   正确可用，确认框会说明真人数、AI 补位数和不可逆影响。
5. 第三名用户断开超过两分钟后，大厅席位自动释放，没有永久占位。
6. 第二名用户释放旧房席位后可以创建独立 4v4 房间 `591519`；两房的席位、准备状态和事件
   没有串房。
7. 匿名观众可在 390×844 视口进入 1v1 观战页，只看到只读观战控制；没有参赛、麦克风或
   房间管理权限。
8. 桌面大厅、移动端 4v4 大厅、匿名观战、注册校验和断线重进均无横向溢出或阻断性布局问题。

## 结果

- 本轮黑盒范围内没有确认新的 High/Medium 产品缺陷。
- 匿名观战会话在测试反复切页时出现过一次 LiveKit `leave-reconnect` 日志，客户端随后自行
  重新连接，没有造成页面白屏或状态丢失；因本轮冻结音频链，记录为观察项，不据此修改播放实现。
- 测试产生的截图只用于当轮人工核对，报告完成后从 Mac 删除，不进入公开 GitHub 快照。
