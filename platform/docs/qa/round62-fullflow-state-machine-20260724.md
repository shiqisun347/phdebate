# Round 62：4v4 完整比赛状态机审计

日期：2026-07-24  
范围：仅后端自动状态机、房间开赛边界和 API 集成测试；未修改前端视觉，未部署，未触碰生产房间。

## 结论

使用正式 `daily-4v4` 流程拓扑完成了一场 4 真人 + 4 AI 的确定性模拟赛。比赛从大厅开始，依次经过预设开场、双方立论、双方驳论、双方质询、自由辩论、双方总结和 AI 裁判，最终生成批准状态的比赛结果。

新增的全流程测试使用 mock Agent、mock TTS、mock ASR 和 mock Judge，不依赖外部服务，因此验证的是平台自己的权威状态、计时、权限、幂等和恢复逻辑。

## 正式流程覆盖

测试文件：`apps/api/tests/test_round62_full_4v4_state_machine.py`

正式流程共 11 个阶段：

1. 开场与规则（预生成主持提示音）
2. 正方一辩立论（真人、mock ASR）
3. 反方一辩立论（AI Agent + mock TTS）
4. 正方二辩驳论（AI Agent + mock TTS）
5. 反方二辩驳论（真人）
6. 正方三辩质询（真人）
7. 反方三辩质询（AI Agent + mock TTS）
8. 自由辩论（双方真人申请、选中、发言和换方）
9. 反方四辩总结（真人）
10. 正方四辩总结（AI Agent + mock TTS）
11. AI 裁判与结果

席位拓扑：

- 真人：`aff_1`、`aff_3`、`neg_2`、`neg_4`
- AI：`aff_2`、`aff_4`、`neg_1`、`neg_3`

最终裁判输入包含 10 条已完成发言，覆盖全部 8 个席位；自由辩论中的预生成 AI 候选不会越过真人申请进入 TTS 或比赛文字记录。

## 同场恢复与安全边界

全流程测试同时验证：

- 房主在首次发言前暂停、继续，重复请求使用同一幂等键只执行一次。
- 真人发言开始、结束和重复结束请求具有幂等性。
- 真人断线超过 60 秒后整场比赛自动暂停，真人席位、用户 ID 和房主身份保持不变。
- 全部真人重连后，只有房主显式继续比赛才会恢复流程。
- 不产生 `seat.ai_substituted` 事件。
- 事件序号始终连续，结束后不存在 `speaking`、`synthesizing` 或 `playing` 残留任务。
- AI 裁判批准后，`Room`、`Match` 和 `JudgeScorecard` 状态一致。

进程重启恢复继续由以下既有测试验证，并已纳入本轮回归：

- `test_round6_engine_recovery.py`
- `test_round12_lifecycle.py`
- `test_round16_engine_resilience.py`
- `test_round19_data_recovery.py`

这些测试覆盖 AI 发言、TTS 播放、裁判任务在引擎重启后的中断、失效结果隔离和可重试恢复。

## 本轮修复的问题

### 1. 已准备但离线的真人仍可被直接 API 开赛

旧逻辑只检查 `is_ready`，没有检查权威在线状态。陈旧页面或直接请求可以锁定一场包含离线真人的比赛，随后立刻进入等待或断线暂停。

修复后，真实运行环境中只要任一真人席位 `connected=false`，开赛接口返回 409，并列出未连接选手；房间保持大厅状态，不创建 `Match`，也不把空席填成 AI。

### 2. 后续主持提示音可能被静默跳过

旧逻辑只把首个提示音作为开赛必需项，其余提示音依赖开赛后的后台绑定。若预设 WAV 缺失、损坏或后台任务尚未完成，进入该阶段时可能直接跳过主持提示。

修复后，当 `host_cues_preset_only=true` 时，开赛前校验冻结流程中的每一条提示音：

- 文本必须与阶段冻结文本一致。
- 预设必须启用且有媒体地址。
- 文件必须是可读取、时长大于 0 的 WAV。
- 任一阶段缺失或文件损坏时返回 409，房间仍在大厅，并明确提示管理员补齐。

Provider 暖机检查被移动到用户可修复条件之后，避免离线或提示音缺失时先返回无关的语音服务错误，也减少无效的暖机调用。
