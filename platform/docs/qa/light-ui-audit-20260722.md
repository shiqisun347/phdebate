# 浅色公共页面改造与验收

日期：2026-07-22  
范围：赛事大厅、全局导航、登录/注册、赛事详情、房间大厅、个人中心与公共非舞台组件。  
不在本次范围：`DebateStage`、ASR/TTS、LiveKit、比赛状态机和 API。

## 设计结论

平台的主要用户是参加 4v4/1v1 辩论的学生。页面的第一任务是让用户迅速知道“我可以参加哪场比赛、下一步应该做什么”。采用浅色操作界面，避免赛前页面和比赛舞台之间出现完全不同的产品语言。

- 画布：`#F5F7FA`；卡片：`#FFFFFF`；正文：`#17233A`；辅助文字：`#66758D`。
- 主操作色：`#1677FF`。成功/警告/错误分别使用低饱和绿、琥珀、红色背景，保证按钮含义稳定。
- 辩论识别元素：蓝色正方—红色反方的细轴线，应用在赛事卡、房间席位和首页的“下一场比赛”预览中。
- 中文正文使用系统无衬线字体，计时和房间号保留等宽数字，避免信息密集区域跳动。
- 移动端 390px：导航折叠、卡片单列、创建/加入按钮保持完整触控高度，房间双方席位改为上下排列。

## 已完成改动

1. `app/globals.css` 增加单一的非舞台浅色产品皮肤，覆盖公共导航、赛事卡片、表单、弹窗、房间大厅、个人中心、状态消息和移动端断点；舞台页面通过 `.stage-page` 隔离，实时音频逻辑不受影响。
2. 首页右侧从持续旋转的装饰轨道改为静态“下一场公开赛”预览：展示辩题、正反方、席位数量、自动赛程、AI 补位和观战标签，减少无意义动画并直接解释产品核心能力。
3. 登录/注册底部切换链接改为可复用的 `auth-switch` 样式，颜色与浅色主操作统一，不再写死暗色紫色。
4. 保留现有无障碍焦点样式、键盘导航、错误重试、房间号复制和触控尺寸；没有修改 DebateStage 的控制、字幕或语音代码。

## 部署后复测清单

- 1440×900：主页赛事卡、公开比赛、排行榜三列/两列切换，无横向滚动。
- 390×844：注册、创建比赛弹窗、房间大厅双方席位、复制房间号、确认开始弹窗均能在视口内完成操作。
- 登录后返回 `/me`，退出/会话错误提示可读且不被导航遮挡。
- `/competitions/daily-4v4` 四个 Tab 在鼠标、键盘和移动端横向滚动下可用。
- `/rooms/:code/lobby` 只检查浅色皮肤，不改变比赛舞台的发言按钮、ASR、字幕和音频播放行为。
- 打开浏览器 console/errors；若出现由 CSS `:has()` 引起的旧浏览器兼容问题，再把非舞台 skin 迁移到由 `MainContent` 注入的 `public-surface` class。
