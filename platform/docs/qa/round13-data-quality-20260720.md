# Round 13：比赛数据质量监控

日期：2026-07-20

## 目标

平台用于持续组织学生辩论并沉淀可复盘数据。原有后台可以盘点媒体文件和归档文件，但不能直接回答正式比赛中的真人逐字稿、录音、分段记录和已发布赛果是否完整。本轮在不修改 ASR、TTS、MOSS、LiveKit、AudioWorklet、PCM 或浏览器播放代码的前提下，增加只读数据质量检查。

## 新增能力

- `GET /api/admin/data-quality` 仅系统管理员可访问，且只统计 `is_test_data=false` 的正式比赛。
- 汇总正式比赛总数、活动比赛、已发布、待复核和已终止数量。
- 分别计算真人完成发言的逐字稿覆盖率、录音覆盖率以及 AI 完成发言数。
- 检查非历史导入比赛中的以下异常：
  - 已发布但没有 approved 裁判结果；
  - 已发布但没有任何发言；
  - 真人完成发言缺少逐字稿；
  - 真人完成发言缺少录音；
  - 真人完成发言缺少 TranscriptSegment。
- 后台“媒体存储”模块顶部增加“比赛数据质量”，展示覆盖率、异常总数和最多 20 条可直接回溯的房间样本。
- QA 比赛不会进入覆盖率和异常样本，避免自动化测试污染正式数据判断。

## 验证

- 自动化构造一场完整正式比赛、一场缺失数据的正式比赛和一场相同缺失的 QA 比赛。
- 断言正式比赛覆盖率为 50%，缺失样本只包含正式比赛，QA 房间不会出现在结果中。
- API 完整回归：417 passed，1 个冻结实时语音竞态按既有规则 xfail。
- Web 完整回归、TypeScript、ESLint 和生产构建通过。
- 可靠音频冻结基线保持 82 个文件，指纹未变化。

## 运营解释

“缺少真人录音”作为数据覆盖提醒，不自动判定比赛无效；管理员仍需结合比赛终止、静音或人工补录场景判断。逐字稿、分段和裁判结果缺失属于更高优先级的数据完整性问题，应在批量导出前处理。
