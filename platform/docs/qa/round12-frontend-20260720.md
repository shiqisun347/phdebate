# Round 12 前端赛事运营与历史体验审计

- 日期：2026-07-20
- 范围：结果页、个人比赛历史、暂停/异常比赛、系统总览、比赛监管、结果复核
- 方法：`frontend-design` 信息架构审计、Vercel React/Next.js 性能规则、生产黑盒问题回放、组件/类型/构建验证
- 冻结边界：未修改 `DebateStage`、TTS、MOSS、LiveKit、AudioWorklet、PCM、ASR 采集或浏览器播放实现

## 设计判断

本轮面向的是大量学生比赛的运营人员和参赛者，而不是通用 SaaS 后台。页面的首要任务是回答三件事：

1. 哪些比赛正在正常推进；
2. 哪些比赛需要人工介入且能够怎样恢复；
3. 哪些记录已经发布、仍待复核或属于 QA 数据。

因此保留现有深色赛事视觉与正反方色彩，只把一次视觉风险用于“运营状态轨”：绿色代表正常推进，琥珀色代表可恢复/待处理，低饱和灰代表终局。没有增加无业务含义的渐变、装饰编号或大面积统计卡。

信息密度参考字节系后台常见做法：筛选和摘要紧邻数据区，异常行具有窄色轨而非整块高饱和警告，主操作保持一个，次操作降级为文字按钮；手机端由宽表切换为纵向任务卡。

## 已确认问题与修复

### 1. 暂停比赛被误写成裁判评议

生产黑盒发现，尚未结束的暂停比赛同时出现“裁判评议中”和“等待管理员复核”，会让参赛者误以为比赛已经结束。

修复：

- 非终局结果页统一使用“实时记录 / 当前比赛状态 / 比赛尚未结束”。
- `paused` 明确说明记录已保存、需等待房主或管理员恢复。
- 只有 `judging` 显示裁判评议，只有 `review_required` 显示人工复核。
- 非终局按钮由“刷新赛果”改为“刷新记录”。
- Hero 图标与色调按进行中、暂停、待复核、终止、已结算分别表达，不再一律使用奖杯。

### 2. 匿名用户可从非终局结果页读取完整历史

前端现已识别后端的 `409` 非终局公开投影响应，并自动返回 `/rooms/:code/watch`。这样匿名观众只进入观战投影，不短暂渲染逐字稿、录音入口或内部赛果页面。

完整安全边界必须由 API 和媒体鉴权保证，不能仅靠隐藏播放器。对应后端权限修复由本轮集成任务实现。

### 3. 少量事件的时间线产生无效空白

- 结果时间线显式使用 `min-height: 0` 和 `align-content: start`，按内容自然增长。
- 0 条事件时给出“时间线正在生成”的方向性空状态。
- 保留已有分页与 `content-visibility`，长记录不一次性渲染全部内容。

### 4. 管理员无法快速识别需要处理的比赛

比赛监管改为紧凑 `AdminRoomSummary`，不再依赖完整 `Room` 运行态对象。页面新增：

- 当前页需处理、运行中、已结束、QA 数量摘要；
- 长期暂停、服务失败、待复核的语义标签与原因；
- 真人在线数、最近更新时间、当前阶段；
- “处理异常”“立即复核”“查看结果”等状态对应主操作；
- 正式/QA 数据的稳定区分。

暂停超过 1 小时且 0 位真人在线会显示为“长期暂停”，但不会自动终止。管理员仍通过单场控制台决定恢复、AI 接替或终止，避免系统擅自处理真实学生比赛。

### 5. 手机端监管仍是横向数据库表

小于 560 px 时，比赛表格转为任务卡布局：辩题在首行，状态、阶段、在线人数和更新时间分组展示，操作区使用至少 42 px 的触控目标。平板仍保留可横向查看的紧凑表格。

### 6. 结果复核缺少证据优先的操作顺序

- 待复核卡先展示失败原因和更新时间。
- 第一入口为“查看比赛记录”，再提供“重试 AI 裁判”和“人工复核”。
- 明确提示待复核结果不会发布或写入排行榜。
- 已确认赛果单独放入低优先级区域，修正仍保留补偿记录与审计轨迹。

### 7. 个人中心无法清楚区分可继续、暂停和 AI 接替

- “进行中”改为更符合用户任务的“需要继续”。
- 暂停比赛显示“查看并等待恢复”，并说明控制台恢复责任。
- AI 接替显示“返回观战”和独立的真人席位恢复申请。
- 历史比赛使用已结算、待复核、终止三种语义色，不再只是相同灰色文本。

### 8. 非管理员访问后台被静默送回首页

后台拒绝后跳转到 `/?notice=admin-required`，首页显示“仅限系统管理员访问”的一次性说明并清理地址栏参数。安全权限不变，但用户不会再把跳转误认为链接失效。

## React 与性能审计

- Admin 模块继续使用动态导入，非当前模块不进入首包。
- 后台各模块独立按需加载；Agent 四组独立请求和媒体两组独立请求均使用 `Promise.all`，未引入串行瀑布。
- 比赛监管切换到 compact projection，避免每页 100 个房间携带 seats、speeches、recent events 等无用运行态；后端同时改为集合查询，消除逐房间序列化查询瀑布。
- 结果页语音元素仍为 `preload="none"`，本轮未触碰播放逻辑。
- 结果逐字稿、时间线和个人历史继续使用分页与 `content-visibility:auto`。
- 新增状态统计仅对当前最多 100 行做单次线性遍历，没有增加 effect、派生 state 或重复网络请求。
- Admin tab 已有 in-flight 去重、请求序列保护和按需缓存，本轮保持该结构。
