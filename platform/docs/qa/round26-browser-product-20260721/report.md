## 结论

公开赛事、认证入口、房间不存在反馈、匿名控制权限和全局观众容量的基础行为正常。桌面与手机布局整体可用，首屏响应快，巡检期间未观察到 JavaScript 异常。

仍有 1 个高优先级隐私/需求冲突：匿名观战页明确保留“比赛发言将在这里实时呈现”的文字稿区域。另有一个生产房间处于服务异常暂停状态，页面同时显示“等待比赛开始”和“比赛已暂停”，但匿名用户无法判断故障是否仍在处理或何时恢复。

## 发现

### ISSUE-001：匿名观战页仍设计为实时展示发言文字

| 字段 | 值 |
|---|---|
| 严重度 | **High** |
| 分类 | privacy / functional / content |
| URL | `https://117.50.192.216/rooms/117519/watch` |
| 证据 | [桌面观战](screenshots/watch-117519-desktop.png)、[手机观战](screenshots/watch-117519-mobile.png) |

匿名观众无需登录即可看到中央文字区域，页面明确写着“比赛发言将在这里实时呈现”。观看设置中只有 AI 语音、麦克风和权威计时状态，没有关闭文字稿的设置。这与“所有观众不可见文字稿”的需求直接冲突；即便当前房间没有实际发言，产品结构和文案都表明实时文字会投影给观众。

复现：匿名打开上述观战链接，观察中央引号面板。桌面和手机均可复现。

建议：服务端的匿名 `watch` 投影彻底删除 transcript/caption 字段，不能只在 CSS 中隐藏；观战舞台把该区域改为当前发言人、阶段提示或纯视觉状态。增加接口与浏览器测试，断言匿名响应、WebSocket 事件和可访问树中均不存在文字稿内容。

### ISSUE-002：生产比赛因临时服务异常暂停，状态表达互相矛盾

| 字段 | 值 |
|---|---|
| 严重度 | **High** |
| 分类 | functional / recovery / ux |
| URL | `https://117.50.192.216/rooms/117519/watch` |
| 证据 | [桌面异常状态](screenshots/watch-117519-desktop.png)、[手机异常状态](screenshots/watch-117519-mobile.png) |

页面持续显示“比赛遇到临时服务异常，已自动安全暂停”，同时主标题是“等待比赛开始”，状态又是“比赛已暂停”。对学生和观众而言，无法区分比赛尚未开始、正在暂停，还是后端仍然故障；页面没有故障发生时间、恢复进度或房主是否已经处理的信息。

复现：匿名打开房间 117519 的观战页即可看到三种状态同时存在。

建议：状态机只投影一个权威主状态。异常暂停单独使用 `paused_service_failure`，展示故障步骤、发生时间、自动重试进度和房主处理状态；“等待比赛开始”只用于尚未开赛。恢复动作继续只对房主/管理员开放，但观众应能看到明确、可更新的恢复状态。

### ISSUE-003：观众满员后仍显示“重连中”和“立即重连”，容易形成请求风暴

| 字段 | 值 |
|---|---|
| 严重度 | **Medium** |
| 分类 | ux / resilience |
| URL | `https://117.50.192.216/rooms/117519/watch` |
| 证据 | [第 6 个观众被拒绝](screenshots/spectator-seventh-overflow.png) |

全站已有 5 位匿名观众时，第 6 位会正确收到“系统观战总人数已达 5 人，请稍后重试”，容量逻辑正确。但页面顶部仍显示“重连中”，并立即提供“立即重连”；与房间自身的服务异常提示叠加后出现两条同色警告。用户可能连续点击，放大满载时的 WebSocket 压力。

复现：用 5 个独立匿名浏览器会话进入观战，再用第 6 个会话进入同一或其他房间。

建议：将容量拒绝视为明确的 `capacity_full` 终态，而非网络重连状态。按钮采用带倒计时的“30 秒后重试”，指数退避并限制点击；同时提供“返回赛事大厅”。容量提示使用独立信息层级，不与比赛故障告警竞争。

### ISSUE-004：匿名访问后台被静默送回首页，没有权限反馈

| 字段 | 值 |
|---|---|
| 严重度 | **Medium** |
| 分类 | auth / ux |
| URL | `https://117.50.192.216/admin`、`/admin/agent-access` |
| 证据 | [匿名后台访问后的首页](screenshots/admin-unauth.png) |

权限边界生效，匿名用户看不到后台内容；但访问 `/admin` 或 `/admin/agent-access` 会静默跳到首页，没有“需要管理员登录”或“无权访问”的反馈。相比之下，匿名访问房间控制台会跳到只读观战并明确提示“只有房主或系统管理员可以进入”，两处权限体验不一致。

建议：未登录访问后台时跳转 `/login?next=/admin...`；已登录但无管理员权限时显示 403 页面，并保留返回个人中心/赛事大厅入口。不要泄露后台数据，但应解释拒绝原因。

### ISSUE-005：登录页缺少账号恢复入口

| 字段 | 值 |
|---|---|
| 严重度 | **Medium** |
| 分类 | missing feature / operations |
| URL | `https://117.50.192.216/login` |
| 证据 | [登录页](screenshots/login-desktop.png) |

平台不要求邮箱或手机号，登录页也没有“忘记账号/密码”或联系管理员的入口。面向大量学生长期使用时，遗忘密码会直接阻断返回比赛、历史和数据归属；即使后台已有人工重置能力，学生也不知道如何发起恢复。

建议：首期提供“申请管理员重置”说明和可复制的用户标识，后台支持一次性临时密码并强制下次登录修改；后续可增加由学校/赛事组织者管理的恢复码。所有重置写审计日志，不能通过真实姓名直接恢复。

### ISSUE-006：手机观战页核心信息层级失衡

| 字段 | 值 |
|---|---|
| 严重度 | **Low** |
| 分类 | responsive / visual |
| URL | `https://117.50.192.216/rooms/117519/watch` |
| 证据 | [390x844 手机观战](screenshots/watch-117519-mobile.png) |

手机首屏中，文字稿占据中央重点位置，之后有大段空白，双方席位被推到较低位置。对观众而言，当前发言人、阶段和队伍状态应比文字面板更重要；在禁止观众查看文字稿后，这块空间更没有存在价值。

建议：移除文字稿后，将当前发言人、阶段、剩余时间组成固定比例的上半屏舞台，双方席位使用紧凑的 2 列网格紧随其后；底部观战工具栏保持固定高度，避免动态状态改变布局。

## 通过项

- 首页、赛事详情、排行榜、登录、注册、房间不存在页在桌面和 390x844 手机视口均可用，没有文字重叠或横向溢出。
- 赛事详情明确显示“全站同时最多 5 人观战”，规则页写明所有房间合计 5 人，辩手、房主和管理员不占名额。
- 实测 5 个匿名观众可同时进入，第 6 个被拒绝；关闭占用会话后，新观众可以再次进入，名额释放正常。
- 匿名访问 `/rooms/117519/control` 被切换到只读观战，并显示具体权限原因。
- 不存在的房间号提供清晰的错误页、房间搜索和返回大厅入口。
- `/v2` 返回产品化 404；本次可见页面未出现“教师”“课程”“全班同意”等遗留课堂文案，也未把 V2 作为产品版本展示。
- 错误账号登录和两次密码不一致均有可访问的行内错误提示。
- 首页冷请求观测 TTFB 约 166ms；同会话缓存导航 DOM 完成约 86ms。浏览器巡检未捕获 JavaScript 异常。

## 测试数据与清理

- 未创建账号、房间、比赛或持久化业务数据。
- 容量测试只建立匿名只读观战连接；测试结束后已关闭所有可用会话，并额外验证释放后新观众可以进入。
- 未开启声音、全屏或麦克风，未调用比赛控制动作。
