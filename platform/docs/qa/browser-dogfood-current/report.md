## 问题

### ISSUE-001：有效房间在开赛前进入观战页显示“页面暂时无法打开”

| 字段 | 值 |
|---|---|
| 严重级别 | P2 / Medium |
| 分类 | 功能 / UX |
| URL | `https://117.50.192.216/rooms/614116/watch` |
| 复现视频 | `videos/issue-001-watch-before-start.webm` |

**现象**

测试房已经创建且房间号有效，但匿名用户打开公开观战链接，在比赛尚未锁定/开始时看到“页面暂时无法打开”，点击“重新尝试”仍停留在同一错误页。预期应显示赛前大厅/等待开赛状态，或明确提示“比赛尚未开始”，而不是通用错误页。比赛开始后需再次验证是否恢复。

**复现步骤**

1. 创建 1v1 训练房，得到房间号 `614116`。
   ![步骤 1](screenshots/issue-001-step-1-watch-before-start.png)
2. 在未开始状态，以匿名浏览器打开 `/rooms/614116/watch`。
   ![结果](screenshots/issue-001-result-watch-before-start.png)
3. 点击“重新尝试”，页面仍显示同一错误。

**影响与建议**

公开分享链接在赛前被用户打开时会形成死路；建议观战路由对 `lobby/ready` 状态返回脱敏的赛前等待页面，并显示房间题目、席位准备进度和预计开赛状态；只有无效/已关闭房间才显示错误页。

### ISSUE-002：自由辩论举手队列遮挡房主“比赛操作”，暂停/终止等控制无法点击

| 字段 | 值 |
|---|---|
| 严重级别 | P1 / High |
| 分类 | 功能 / UI / 房主恢复能力 |
| URL | `https://117.50.192.216/rooms/614116/debate` |
| 复现视频 | `videos/issue-002-control-overlay.webm` |

**现象**

进入自由辩论后，房主打开底部“比赛操作”面板，面板中的“暂停比赛”“提前结束比赛”“仅退出比赛页面”位于右侧举手队列组件下方。浏览器命中测试确认点击会落在 `.free-turn-queue`，实际按钮无法操作。此时如果自动流程或服务异常，房主无法使用最关键的现场恢复控制。

**复现步骤**

1. 以房主身份进入正在进行的自由辩论。
   ![步骤 1](screenshots/issue-002-step-1-free-debate.png)
2. 点击底部“比赛操作”。
   ![步骤 2](screenshots/issue-002-step-2-control-open.png)
3. 点击“暂停比赛”。
   ![结果](screenshots/issue-002-result-control-covered.png)
4. **观察：** 点击被右侧自由辩论举手队列截获，比赛没有暂停；自动倒计时仍继续运行。

**影响与建议**

这是完整比赛流程的现场恢复阻断问题。应让固定底部控制层拥有明确高于舞台侧栏的层级，并为展开面板预留/覆盖安全区域；同时补充真实点击测试，确保桌面和移动端的暂停、终止、退出按钮均能点击。

### ISSUE-003：手机端“文字记录”浮层遮挡“比赛操作”，房主无法打开恢复控制

| 字段 | 值 |
|---|---|
| 严重级别 | P1 / High |
| 分类 | 功能 / 移动端 / 房主恢复能力 |
| URL | `https://117.50.192.216/rooms/304717/debate`（390×844） |
| 复现视频 | `videos/issue-003-mobile-operation-covered.webm` |

**现象**

手机端固定控制栏右侧的“比赛操作”按钮被悬浮的“文字记录”按钮覆盖。视觉上已经明显叠在一起，浏览器命中测试确认点击会落在 `.stage-transcript-trigger`，房主无法打开暂停、提前结束、退出等操作。切换到桌面宽度后同一控制可以正常使用。

**复现步骤**

1. 以房主身份在 390×844 视口进入辩手页。
   ![步骤 1](screenshots/issue-003-step-1-mobile-controls.png)
2. 点击底部控制栏的“比赛操作”。
   ![结果](screenshots/issue-003-result-mobile-operation-covered.png)
3. **观察：** 点击被“文字记录”浮层截获，操作面板没有展开。

**影响与建议**

移动端是学生常用设备，这会直接移除异常时的房主恢复入口。应将文字记录整合到固定底栏内，或在移动端放入同一个“更多”菜单；必须为固定控制项设置互不重叠的点击区域并增加 390×844 真点击回归测试。

### ISSUE-004：开赛系统提示音在浏览器端报告“加载或解码失败”

| 字段 | 值 |
|---|---|
| 严重级别 | P1 / High |
| 分类 | 音频 / 功能 / 现场体验 |
| URL | `https://117.50.192.216/rooms/304717/debate` |
| 复现视频 | `videos/issue-004-mobile-audio-retry.webm` |

**现象**

开赛进入“训练开始”自动流程后，页面出现红色错误：“比赛音频加载或解码失败，请点击‘重试比赛声音’。打开比赛控制台重试当前发言”。同类状态在桌面首场测试中也出现过“重试比赛声音”。流程仍会推进，但学生会错过主持提示音，且把播放器错误误认为整场比赛异常。

**证据**

1. 手机端开赛自动流程出现音频加载/解码错误。
   ![音频错误](screenshots/issue-004-step-1-audio-error.png)
2. 自动流程随后进入下一阶段，错误入口消失，用户没有机会确认失败提示音是否已经补播。
   ![阶段推进后](screenshots/issue-004-result-after-retry.png)

**影响与建议**

主持预设音是流程导航的一部分。应区分浏览器自动播放被阻止、音轨尚未到达、真实解码失败三种状态；若只是未解锁音频，使用中性“点击开启比赛声音”，不要显示红色故障。真实解码失败应保留可重试状态，重试成功后明确反馈，并记录可关联的音轨/阶段错误码。

### ISSUE-005：手机端赛前大厅固定底部导航覆盖席位卡内容

| 字段 | 值 |
|---|---|
| 严重级别 | P2 / Medium |
| 分类 | 移动端 UI / UX |
| URL | `https://117.50.192.216/rooms/304717/lobby`（390×844） |
| 复现视频 | N/A（静态可见） |

**现象**

赛前大厅的固定底部导航横跨页面中部并覆盖席位卡和“点击空席加入”区域。用户滚动浏览席位时，内容会被导航遮住，认领席位、确认人员状态的阅读连续性较差。

**证据**

![手机端大厅](screenshots/lobby-mobile-full.png)

**影响与建议**

赛前大厅应优先展示席位和开赛动作。建议移动端大厅隐藏全局底部导航，或为可滚动内容增加与固定栏等高的安全区；更简洁的方案是只保留房间内的返回、分享和主要动作，不继续展示全站导航。

### ISSUE-006：自由辩论提示“系统正在安排 AI 接替”，但最终没有产生任何自由辩论发言

| 字段 | 值 |
|---|---|
| 严重级别 | P2 / Medium |
| 分类 | 自动流程 / 状态文案 / 功能完整性 |
| URL | `https://117.50.192.216/rooms/614116/debate` |
| 复现视频 | `videos/issue-002-control-overlay.webm`（同时记录该状态） |

**现象**

双真人 1v1 的自由辩论中，双方均未在申请窗口内发言。页面明确显示“本轮无人申请，系统正在安排 AI 接替”，随后却只是不断交换发言方并结束自由辩论。结果页总发言数为 4，恰好只有双方立论和总结，说明 AI 接替没有实际产生自由辩论发言。

**证据**

1. 页面承诺安排 AI 接替：
   ![AI 接替提示](screenshots/issue-002-result-control-covered.png)
2. 赛后摘要仅有 4 次发言，没有自由辩论内容：
   ![赛后摘要](screenshots/result-desktop-full.png)

**影响与建议**

这会让核心的自由辩论环节在学生没有及时操作时变成空转。需要明确产品决策：若确实要 AI 接替，应生成并播放一次受时长限制的发言；若不接替，应改为“本轮无人申请，交换发言方”，不要承诺不存在的动作。还应限制连续空轮次数，避免用户看着 00:00 和换方状态反复跳变。

## 通过项

- 新用户注册后自动登录正常；退出后重新登录成功。
- 第二名登录用户能够认领空席，房主能移出该用户，双方准备后才允许锁定开赛。
- 空席在房主开始时自动补为 AI；开赛确认会说明锁定席位、AI 补位和不能更换题目/席位。
- 固定轮次只有当前真人辩手能发言，其他辩手按钮显示具体等待原因。
- 麦克风不可用时的文字发言可以完成当前发言并推进阶段。
- 真人发言期间房主暂停按钮禁用并解释“真人发言结束后可暂停”，避免中途破坏语音提交。
- 双真人比赛最终进入 AI 裁判和结果页，个人分、裁判理由和时间线均可加载。
- 匿名观众在比赛进行中只能查看舞台；结果页不显示字幕/发言文字，只显示比分、裁判理由和脱敏时间线。
- 房主可在桌面宽度打开比赛操作、确认提前结束，并得到“比赛已终止”结果页。

## 未覆盖/限制

- `agent-browser` 环境没有可用于质量评估的真实麦克风输入，无法评价 FunASR 双流式、端点检测、字幕识别准确率；本轮使用产品内置文字发言作为真人流程替代。
- 无法通过截图客观判断 TTS 音色、杂音、撕裂、语速和首音延迟；本报告只记录浏览器显示的音频加载/解码异常状态。
- 未进行 4v4 八席多人同步和 5 个匿名观众并发压力测试；本轮优先证明单场 1v1 完整流程和可恢复性。
