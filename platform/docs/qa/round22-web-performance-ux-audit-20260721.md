# Round 22 非冻结页面性能与体验审计

日期：2026-07-21  
范围：首页、赛事详情、登录/注册、个人中心、排行榜、管理后台、房间大厅与结果页。  
明确排除：`debate-stage.tsx`、实时语音链路、浏览器播放实现及所有冻结音频文件。

## 结论

当前公开页面已经形成稳定、克制的深色赛事视觉，桌面与 390×844 手机宽度均未发现横向溢出、控件遮挡或不可达主操作。首页生产环境实测 TTFB 24.9ms、FCP 132ms、LCP 284ms、CLS 0.00；注册页 TTFB 43.2ms、FCP/LCP 112ms、CLS 0.06。此次不做大范围换肤，优先修复能由代码与测试证明的操作可靠性、视觉稳定性和产品语言问题。

## 已修复问题

### 1. 首页排行榜重试会短暂显示错误空状态，并允许请求竞态

- 严重度：中
- 影响：弱网下用户点击“重新载入排行榜”后，请求尚未结束，界面可能提前显示“完成首场积分赛后……”；重复操作也可能产生并行请求并由较慢响应覆盖较新结果。
- 修复：为榜单请求增加单飞保护、明确的 `rankingsLoading` 状态、`aria-busy` 和“正在重新载入排行榜…”反馈。正在请求时不再展示误导性的空榜文案。
- 验证：`public-pages.test.tsx` 新增未决请求与重复点击用例，确认只产生一次重试请求。

### 2. 退出登录失败是无反馈的未处理操作

- 严重度：中
- 影响：网络波动时点击退出会抛出失败，但导航没有状态、错误或重试入口；用户无法判断账号是否仍登录，重复点击还可能并发提交。
- 修复：增加提交锁、忙碌状态、可见且可访问的错误提示，以及“重试退出”动作。只有服务端确认成功后才更新会话并跳转。
- 验证：`global-nav.test.tsx` 模拟首次断网、第二次成功，确认失败不跳转、成功后才返回大厅。

### 3. 注册页会话确认阶段造成首屏高度跳变

- 严重度：低（感知质量）
- 证据：生产注册页浏览器指标 CLS 为 0.06；页面先显示一行会话确认提示，再替换为较高的完整注册表单。
- 修复：登录与注册分别预留接近最终表单的稳定高度，避免认证状态解析时卡片和页脚明显下跳。该方式不延迟表单、不引入骨架动画，也不会增加 JavaScript 包。
- 验证：认证组件测试确认注册态使用稳定占位类；需在部署后复测真实 CLS。

### 4. 房间大厅残留英文内部术语

- 严重度：低
- 影响：`Room Lobby` 与全站中文赛事语言不一致，像工程页面而非面向学生的正式产品。
- 修复：统一为“赛前大厅”，不改变路由、状态或比赛逻辑。
- 验证：房间大厅测试确认页面不再出现旧英文术语。

## 设计与性能判断

- 保留当前蓝紫主色、正反方蓝红分界线和高密度赛事卡片；它们与“竞技、秩序、双方对抗”的产品语义一致，不建议照搬通用后台模板。
- 首页主操作在手机上保持整行触控区域，赛事卡片信息层级清楚；注册页字段间距与触控高度符合移动端使用。
- 管理后台已经对重模块使用 `next/dynamic`，并按标签延迟载入数据；本轮没有发现值得以架构风险换取的进一步拆包点。
- 长列表已经使用 `content-visibility`，排行榜和管理表格有移动端重排/横向滚动提示。
- 本轮未修改结果页中的音频回放代码，也未修改任何舞台组件和语音文件。
