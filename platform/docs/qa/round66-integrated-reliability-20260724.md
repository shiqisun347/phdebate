# Round 66 单场比赛可靠性综合报告

日期：2026-07-24

## 本轮修复

1. 真人获得固定阶段或自由辩论发言权后，新增独立的 120 秒开口准备期限。期限内正式发言钟和自由辩论总时钟均冻结。
2. 超时后只执行安全暂停，保留原真人席位、阵营、阶段、`turn_seq` 和双时钟；不创建发言、不跳阶段、不触发 AI 接管。
3. 房主恢复后仍由原真人完成原轮次。页面将其归类为“人员准备暂停”，只提供继续，不显示服务重试，也不允许用跳过掩盖。
4. 开场准备阶段可由房主暂停和恢复，避免设备或会场尚未就绪时控制台没有可用操作。
5. 修复匿名观众进入公开房间时的 RTC 凭证竞态：先完成房间 WebSocket 握手并取得观战凭证，再申请 LiveKit token。
6. 生产发布门强制系统提示音只使用预设文件，拒绝 6016、Qwen3 8B、比赛音频归档和退役 TTS 流式路径；旧主持人入口不再可达。
7. 两份唯一官方文档已同步真人开口超时、恢复方法和预设提示音规则。

## 生产问题证据

生产房间 `117519` 长时间停在自由辩论，当前选中真人为 `neg_2`，`awaiting_human_start=true`，没有活跃发言且比赛总时钟冻结。旧版本没有开口准备期限，因此房间会无限占用运行状态。

新版本部署后，旧房间不会被立即暂停：Engine 首次处理会先补一个完整 120 秒期限；仍未开始才安全暂停。恢复后仍为 `neg_2` 当前轮次。

匿名观战完整 E2E 还稳定复现过 `POST /api/rooms/:code/rtc-token → 403`。原因是页面根据首次 HTTP snapshot 提前申请 RTC token，而匿名观战凭证要在房间 WebSocket 握手时建立。本轮已将 RTC 初始化绑定到实时房间连接完成状态，并增加回归测试。

## 未部署原因

生产仍有运行中的房间 `117519`。本轮包含 Engine 状态机和 Web 实时连接改动，在活动比赛中重启会扩大现场风险，因此不执行部署或服务重启。发布前必须确认没有活动比赛，再原子切换并用完整 1v1/4v4 canary 验收。

## 已确认但尚未实施的 P0 音频缺口

AI 发言已经通过每房间唯一 `agent-tts` LiveKit 音轨播放，但固定系统提示音仍由浏览器 `new Audio(...)` 播放。整场比赛因此仍有两类下行播放链，不完全满足“浏览器只接收一条连续 WebRTC 音轨”。

下一语音改造必须复用现有 `LiveKitRoomAudioPublisher`，把预设 WAV 解码为 PCM 后送入同一 publisher，并以 LiveKit playout drain 作为提示结束和阶段推进的权威边界；同时将 LiveKit client 提升到房间 layout 跨 lobby/debate/watch 保活。该改动不需要引入新框架，但必须在无活动比赛时一次性切换，并用音频协议版本阻止旧浏览器产生双声。
