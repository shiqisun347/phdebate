生产环境：`https://117.50.192.216`
范围：匿名赛事大厅、赛事详情、注册登录、双真人 1v1 大厅、开赛跳转、个人中心、桌面与 390px 手机布局、断线/设备控制提示。

## 结论

- 两个独立浏览器会话完成注册、创建公开训练房、第二位真人入席、准备和开赛；剩余席位与房间状态没有串到其他房间。
- 服务端 WebSocket 初始及后续 snapshot 均按会话返回正确的 `my_seat`、`can_control` 和 `is_me`。第二个复现房中，房主始终为 `aff_1`，加入者始终为 `neg_1`。
- 首个复现房曾出现加入者开赛首屏短暂采用错误席位/设备控制状态，但同一时刻认证 REST 返回正确 `neg_1`；第二个受控复现房无法再次触发。根因收敛为初始 REST 与较新 WebSocket state 的时序合并，而不是服务端跨用户广播。
- 可靠 TTS、浏览器音频、AudioWorklet、LiveKit 和 DebateStage 均未修改。

## 已修复问题

### 1. 开赛首屏的认证投影可能被时序丢弃

`useRoom` 原先只在 REST 的 `seq` 不小于当前状态时采用整个响应。初始化期间，如果共享比赛状态先通过 WebSocket 推进，随后返回的认证 REST 即使包含正确的 `my_seat`、发言权限和恢复申请，也会因 `seq` 较低被完全丢弃。

修复后：

- 较新的共享比赛状态继续保留；
- 较低序号的认证 REST 只合并当前用户专属字段；
- 同序号 WebSocket snapshot 不再覆盖已经确认的认证投影；
- 不会为每条 WebSocket 事件额外发起 REST 请求，因此没有放大大房间的请求量。

新增回归覆盖 `my_seat`、`can_control`、`can_speak`、`speak_reason`、恢复申请和各席位 `is_me`。

### 2. 390px 赛事标签边缘过紧

赛事详情的四个标签在 390px 视口末端贴近边界。移动端间距由默认值收紧为 `6px`，保持无横向滚动，并让“规则说明”完整留在安全区域内。

### 3. 个人中心进行中比赛说明重复

进行中卡片原先会重复展示“进行中”。现在状态徽标负责状态，说明文字改为“点击返回当前发言与计时画面”；暂停、大厅和 AI 接替仍显示各自可执行的恢复动作。
