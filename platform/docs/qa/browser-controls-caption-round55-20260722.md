### ISSUE-001：真人尚未开始发言，环节倒计时已持续扣减

| 字段 | 内容 |
|---|---|
| 严重级别 | high |
| 分类 | functional / ux |
| URL | `https://117.50.192.216/rooms/378662/debate` |
| 复现视频 | [issue-countdown-before-speech.webm](assets/browser-controls-caption-round55/videos/issue-countdown-before-speech.webm) |

**问题描述**

进入“反方立论”后，页面明确显示“等待下一位辩手”“待发言”，主按钮仍为“开始发言”。在辩手没有点击按钮、没有取得麦克风、也没有提交文字的情况下，计时器从 `01:56` 降至 `01:44`。这会把设备准备、阅读阶段提示以及主持提示音占用的时间计入真人有效发言时间，尤其会惩罚首次授权麦克风或需要切换文字兜底的学生。

预期应将“环节准备/提示音时间”与“真人有效发言时间”分离：进入阶段先冻结正式倒计时；当前真人明确开始语音/文字发言后才启动倒计时。若赛事规则确实要求自动计时，也应在按钮旁显示清晰的开计时规则和即将自动开始的倒数，而不是同时显示“待发言”。

**复现步骤**

1. 两名真人认领 1v1 正反方席位并确认准备，房主确认开始比赛。
2. 正方完成立论，系统进入“反方立论”；反方保持不操作，页面仍显示“待发言”和“开始发言”。此时剩余时间为 `01:56`。
   ![开始观察](assets/browser-controls-caption-round55/screenshots/issue-001-countdown-step-1.png)
3. 等待 12 秒，不点击任何按钮。
4. **观察：** 页面仍显示“待发言”和“开始发言”，但剩余时间已变为 `01:44`。
   ![倒计时已扣减](assets/browser-controls-caption-round55/screenshots/issue-001-countdown-result.png)

### ISSUE-002：过期文字发言入口跨阶段保留，当前输入会无提示归档到旧阶段

| 字段 | 内容 |
|---|---|
| 严重级别 | high |
| 分类 | functional / ux |
| URL | `https://117.50.192.216/rooms/378662/debate` |
| 复现视频 | N/A（本次为轮次到期竞态，使用连续截图记录） |

**问题描述**

反方在“反方立论”临近结束时打开“改用文字完成本轮发言”。服务端仍在准备/锁定轮次时，比赛已经自动进入“自由辩论”，但旧阶段的文字弹窗没有关闭，仍明确提示“当前轮次已为你保留”，输入框和提交按钮也仍可用。输入并提交后弹窗直接消失，没有告知内容仍会归入已经结束的“反方立论”；用户查看当前自由辩论文字记录时只会看到 0 条，无法判断提交结果。

同一问题还可在自由辩论轮次切换和阶段结束后复现：上一轮打开的文字入口跨轮次保留。正方进入“正方总结”后，页面仍显示来自自由辩论的“文字内容仍在本页 / 继续文字发言”。用户自然地把当前总结输入该入口并提交，但赛后记录把这段总结归到了“自由辩论”，AI 裁判也基于错误的阶段结构进行评价。

这会把学生的观点归档到错误阶段，并直接污染裁判所见的辩论结构。应在阶段/轮次 token 变化时立即把旧弹窗标成“上一轮草稿”，明确显示目标阶段和目标辩手；默认禁止继续直接提交到过期轮次。用户应能复制草稿，或明确确认“作为上一轮补交”。如果用户正在当前阶段发言，则应引导重新建立当前轮次的发言会话，不能让旧 CTA 看起来像当前发言入口。

**复现步骤**

1. 在固定发言阶段临近计时结束时，点击“改用文字发言”，等待输入区域准备。
2. 不提交，直到系统自动切换到“自由辩论”。
3. **观察：** 页面主体已是“自由辩论”，旧弹窗仍称“当前轮次已为你保留”，输入框和提交入口仍存在。
   ![旧阶段弹窗跨阶段保留](assets/browser-controls-caption-round55/screenshots/issue-002-stale-text-dialog-step-1.png)
4. 输入用于验证的文字，提交按钮正常可用。
   ![过期轮次仍可编辑提交](assets/browser-controls-caption-round55/screenshots/issue-002-stale-text-dialog-step-2.png)
5. 点击提交。
6. **观察：** 弹窗直接消失，没有保存/拒绝/归档阶段提示；自由辩论当前阶段仍显示没有对应的已完成发言。
   ![提交后无结果说明](assets/browser-controls-caption-round55/screenshots/issue-002-stale-text-dialog-result.png)
7. 在后续“正方总结”再次通过残留的“继续文字发言”入口输入并提交完整总结。
8. **观察：** 页面仍显示“待发言”，当前阶段文字记录为 `0 条已完成发言`，且没有说明该内容其实被提交到了旧的自由辩论轮次。
   ![当前阶段看不到已提交内容](assets/browser-controls-caption-round55/screenshots/issue-002-lost-summary-result.png)
9. 完成比赛并查看赛后完整记录。
10. **观察：** 用于“正方总结”的完整文本被标记为“自由辩论”；用于验证过期弹窗的文本被标记为“反方立论”，证明旧入口会无提示提交到历史轮次，而不是当前页面所示阶段。
    ![赛后阶段归档错位](assets/browser-controls-caption-round55/screenshots/result-transcripts-stage-attribution.png)

### ISSUE-003：390×844 下自由辩论队列、文字兜底入口与固定控制栏互相遮挡

| 字段 | 内容 |
|---|---|
| 严重级别 | medium |
| 分类 | visual / ux / responsive |
| URL | `https://117.50.192.216/rooms/378662/debate` |
| 复现视频 | N/A（稳定可见的响应式布局问题） |

**问题描述**

在 390×844 手机视口、自由辩论且存在未完成文字草稿时，底部固定控制栏、自由辩论举手队列和“文字内容仍在本页 / 继续文字发言”浮层占用同一区域。队列的说明和申请按钮被控制栏及深色浮层部分遮挡，难以确认当前是否能举手；多个高优先级入口争夺底部空间，也会增加误触。

应为固定控制栏预留稳定的内容安全区，并把“继续文字发言”并入控制栏的状态区域或队列卡片上方，避免三层浮动 UI。自由辩论队列在手机端宜采用可展开的单行抽屉，默认只显示下一阵营、队列人数和主操作。

**复现步骤**

1. 将比赛页调整为 390×844。
2. 进入自由辩论，并在文字发言弹窗中留下未完成状态后返回舞台。
3. **观察：** 队列卡片、深色“继续文字发言”入口和固定控制栏发生视觉遮挡。
   ![手机底部区域重叠](assets/browser-controls-caption-round55/screenshots/issue-003-mobile-overlap.png)

### ISSUE-004：阶段切换仍使用“主持人”概念，且把提示音倒数伪装成发言剩余时间

| 字段 | 内容 |
|---|---|
| 严重级别 | medium |
| 分类 | content / ux |
| URL | `https://117.50.192.216/rooms/378662/debate` |
| 复现视频 | N/A（阶段切换时稳定出现的状态文案） |

**问题描述**

系统已经采用自动赛程、没有主持人角色，但阶段切换时底部仍显示“主持人正在播报下一环节”。同时中央已经切换为“反方立论”，计时器显示 `00:06` 且标注“本环节剩余”，待提示音结束后计时又跳回约两分钟。用户无法判断这 6 秒是提示音时长、正式发言倒计时还是阶段即将结束，和随后“待发言”的状态互相矛盾。

建议统一改为“系统正在播放阶段提示”，并把提示音进度设计成独立的短进度条或“约 6 秒后可发言”；正式发言计时在辩手取得发言权前应隐藏或保持冻结，避免跳变。

**复现步骤**

1. 真人提交某个固定阶段发言。
2. 观察系统切换到下一阶段时的舞台和底部控制栏。
3. **观察：** 舞台已显示“反方立论”，倒计时为 `00:06 / 本环节剩余`，底部却显示“主持人正在播报下一环节”；稍后正式计时又跳回完整时长。
   ![阶段提示与计时语义冲突](assets/browser-controls-caption-round55/screenshots/after-owner-text-submit.png)

### ISSUE-005：赛后完整文字记录对比度过低，长篇内容难以阅读

| 字段 | 内容 |
|---|---|
| 严重级别 | medium |
| 分类 | visual / accessibility |
| URL | `https://117.50.192.216/rooms/378662/result` |
| 复现视频 | N/A（稳定可见的视觉问题） |

**问题描述**

赛后“完整辩论文字记录”的正文使用非常浅的蓝灰色显示在白色卡片上。普通桌面截图中已经明显发虚，连续阅读多段长文本较吃力；这与“回溯学生辩论数据”的核心使用目标冲突。手机结果页的说明文案也采用相近的浅色。

建议正文使用接近主文本的深色（普通正文至少满足 WCAG AA 4.5:1），仅把时间、类型等元信息降一级；不要对整段发言使用低透明度。历史记录应支持清晰的段落行距、当前检索高亮与按阶段折叠。

**复现步骤**

1. 完成比赛并进入结果页。
2. 滚动到“完整辩论文字记录”。
3. **观察：** 所有长篇发言正文与白色背景对比度很低，明显弱于标题和元信息。
   ![赛后文字记录低对比度](assets/browser-controls-caption-round55/screenshots/result-transcripts-stage-attribution.png)

## 已通过的检查（持续补充）

- 两个独立登录用户可进入同一 1v1 房间、分别认领正反方席位并确认准备。
- 房主开赛采用二次确认，文案说明席位锁定、空席补齐和短暂准备过程。
- 确认开赛后立即进入比赛页；本次未出现无反馈的长时间空白等待。
- 桌面端主发言按钮与声音、全屏、操作按钮固定在页面底部；主操作视觉层级清楚。
- 非当前发言人无法操作发言按钮；轮到本人时按钮显示“开始发言 / 轮到你发言”。
- 房主暂停后，两个用户页面同步进入暂停状态，计时器冻结；房主继续后同步恢复。
- 自由辩论中，只有下一发言阵营可举手；申请成功后席位显示“已选中”，下一轮正确切换到该辩手。
- 匿名观战页为只读模式，未出现“文字记录”或发言控制入口。
- 1v1 双真人比赛最终完成全部阶段、生成裁判结果并跳转结果页；两名参赛者都能看到完整赛果。
- 结果页在 390×844 下主要操作纵向排列，没有横向溢出，胜负和分数清晰。

## 本轮未能完全验证

- agent-browser 的无头 Chromium 未获得真实麦克风权限，因此无法通过真实语音制造 ASR 增量字幕。本轮已经验证无麦克风时的文字恢复链路、字幕/阶段提示容器和观战脱敏，但“ASR 增量是否始终按电视剧式单行滚动”仍需在具备真实麦克风的桌面浏览器中补一轮带语音证据的测试。
- 本轮未把音频自动播放警告列为产品缺陷：浏览器在用户首次交互前阻止 `audio.play()` 属于平台策略，页面已经提供“开启比赛声音”入口。后续仍应验证用户点击后不会重复出现解锁提示。
