## 主要修复

- API 拆成 12340 primary 与 12342 secondary；比赛引擎只在独立 Engine 进程运行。
- REST 与纯房间状态 WebSocket 使用 least-connection 分流；音频、ASR 和私有媒体继续固定
  到经过验证的 primary，不改变可靠播放路径。
- Presence 改为 Redis ZSET 租约和 Lua 原子操作；同一真人跨两个 Worker 连接时，只有最后
  一条连接关闭才写入离线事件。
- 匿名观战订阅交接的同步数据库校验移出 ASGI 事件循环，避免观众突发阻塞新握手。
- Nginx 提升文件句柄、连接和监听队列；滚动发布期间禁用持久被动摘除，避免两个健康实例
  被同时标记为不可用。
- 修复滚动脚本 `set -u` 下临时链接变量提前展开，并为公网健康门禁增加有限重试和自动回滚。
- Admin 首页请求从 14 个降为 1 个；比赛、用户、Agent 等域按访问懒加载并缓存。
- Admin 大组件拆出系统总览、比赛监管、用户管理和分页组件，降低后续修改冲突。
- 首次加载不再同时显示“共 0 条”和“没有结果”。
- 自由辩论空闲态明确标记当前可发言阵营和全部合法席位；固定轮次仍只标记唯一发言者。
- 真人恢复控制台使用“正方一辩”等可读名称，并显示申请者是否仍在线。
- 删除比赛页对退役组织录音同意流程的运行时调用；教师、课堂、课程不再出现在运行时产品域。
- 源码备份脚本兼容本地 `v2` 和服务器 `phdebate` 目录，并排除 GPU 虚拟环境、构建产物、
  运行时指针、密钥和数据卷。

## 发布中发现并修复的故障

首次滚动发布时，Nginx `max_fails=1` 在两个 Worker 依次重启后把二者都标记为不可用，
导致公网 API 502，而两个直连健康接口均为 200。浏览器回归捕获了四个首页核心接口同秒
502。立即重载恢复后，已改为滚动发布兼容配置并重新发布；此后浏览器 5xx 为 0。
