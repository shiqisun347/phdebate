## 问题明细

### ISSUE-001（Medium）已登录用户仍可打开并提交注册页

- 范围：`/register`。
- 复现：先登录任意账号，再直接访问 `/register`。
- 实际：页头已显示当前真实姓名和“退出登录”，但完整注册表单仍可用。黑盒流程中已实际成功新建另一账号，当前会话被无提示替换为新账号。
- 影响：学生误入注册页可重复建号，导致历史记录、席位和排行榜身份被拆分；这与“真实姓名账号用于返回比赛和数据归档”相冲突。
- 证据：生产双账号复现、服务端用户计数和会话切换均已记录；临时截图按“不在 Mac 保留测试归档”规则在收口后删除。
- 修复：
  - 前端 `AuthForm` 在 session 未确定时不显示表单；确认已登录后跳转安全 `next` 路径或 `/me`，切换账号必须先显式退出。
  - 服务端 `POST /api/auth/register` 重新检查有效 session；已登录请求返回 `409`，不创建用户、不切换会话。
  - 前端聚焦测试 `25/25` 通过、TypeScript 通过；API 聚焦测试 `2/2` 通过、Ruff 通过。
- 当前状态：本地源码已修复，生产仍需部署后复验。

## 核心黑盒结果

- 1v1：题库与自定义题目互斥正确；房主选反方、参赛者认领正方，双方准备后仅房主出现“锁定席位并开始”。本轮未点击开始。
- 多设备：同一房主的新设备登录后默认只读，只有点击“确认接管到当前设备”后获得控制权；旧设备实时降级为只读。刷新后控制权保持。
- 断网：参赛者离线时本页立即显示“正在重连”及可操作的“立即重连”；房主视图在约 1.5 秒内将该辩手标为离线；恢复网络刷新后席位和准备状态无丢失。
- 4v4：题库切换、8 席位创建、六位房间号搜索、非数字过滤、座位释放均正常。
- 并发抢座：两个隔离账号同时认领同一席位，权威状态只有一个成功；请求结果为一个 `200` 和一个 `409`，失败方持续显示“该席位已被占用”，没有两人同座或静默失败。
- 房主权限：普通参赛者无开始、关房、移出他人控件；房主不可自行释放房主席位，可移出阻塞开赛的其他参赛者。
- 房间终态：1v1 `338151` 与 4v4 `517051` 均经房主确认关闭，其他在线用户自动回到赛事大厅；取消房间不会被导向错误观战页。
- 个人中心：待开赛房间显示清晰的“等待房主锁定席位并开始比赛 / 返回房间大厅”；“退出其他设备”保留当前会话并撤销旧设备。
- 权限：普通用户直访 `/admin` 被导回首页；未登录直访 `/me` 跳转 `/login?next=/me`。
- 匿名观战：公开已完成房间 `367133` 可匿名读取赛果、评议、记录与时间线，页面无任何房主/辩手写操作。未开赛 lobby 的匿名直链返回 `401`，不泄露席位信息。

## 未修风险

- 本轮为保护已冻结的可靠音频基线，不启动比赛，因此未黑盒重测运行中的 Agent、TTS、ASR、麦克风录制、辩手发言权和比赛内断线 AI 接替；这些由非音频单元/引擎测试与专门音频窗口覆盖。
- 未开赛房间的匿名 watch 直链显示通用“页面暂时无法打开”；权限上是安全的，但如产品希望开赛前也可分享观战链接，后续应提供“比赛尚未开始”的专用只读状态，而不是通用错误页。
- “关闭房间”与“退出其他设备”仍使用浏览器原生 `confirm`，功能和键盘操作正常，但视觉上不符合当前设计系统；可作为后续低风险体验改进，不建议在本轮扩大改动。
- QA 清理已完成：三个测试账号均为 `is_test_account=true / is_active=false`，残留 session 为 0；房间 `338151`、`517051` 均为 `cancelled / is_test_data=true`，席位连接、准备状态和控制租约残留为 0。
