# Round 20：固定阶段 Agent 文本安全预取

日期：2026-07-21

## 结论

已为“立即下一位、永久 AI 席位、固定发言阶段”增加进程内文本预取。预取只调用 Debate Agent 生成文字，不创建 `Speech` 权威记录，不启动 TTS，不占用 LightTTS/LiveKit 声道，也没有修改冻结的实时语音基线。

主持人口播阶段会开始预取；当前 AI 流式回复的最终文字固定后，也会在原生音频仍可能继续排空时预取下一固定发言。下一阶段真正开始时，只有完整有效性指纹仍一致，文字才会进入原有单会话实时 TTS 流程。

## 有效性与隔离

缓存指纹覆盖：

- 房间、比赛、题目；
- 目标阶段完整快照和阶段序号；
- 席位、占用类型、显示名和 Agent Profile；
- Profile 模型、版本更新时间；
- 截至当前已固定的完整辩论历史；
- 开赛时冻结的 Agent Provider 配置快照。

以下情况均会取消或丢弃预取：

- 房间暂停、终止或进入裁判阶段；
- 跳过目标阶段或阶段序号变化；
- 题目、模板、人设、服务快照发生变化；
- AI 席位被人类认领、恢复或变成 AI substitute；
- 当前发言中断，导致其固定文字不再属于有效历史；
- 引擎停止或事件循环重建。

缓存严格按六位房间号隔离。任务 ID 由完整指纹生成 UUIDv5；相同输入可由上游幂等复用，服务重启后本地非权威缓存允许消失并安全重算。

## 调度策略

- 每个房间最多一个固定阶段预取任务和一个可用缓存。
- 正式 AI 发言开始时会抢占所有仍运行的固定阶段预取任务，正式比赛不会排在推测任务之后。
- 已完成的文本缓存不占 Provider 或语音并发槽。
- 自由辩论不使用本机制，避免与自由辩论的 should-speak 决策/候选生成发生语义冲突。

## 可追溯性

预取本身是非权威性能缓存，不写入比赛历史。真正消费时写入不含正文和密钥的 `speech.content.prefetched` 事件；最终正文仍由正常 `Speech`、字幕、音频和归档链路负责。

- `test_round20_agent_prefetch.py`：3 项通过。
- 与字幕、自由辩论队列和 should-speak 场景组合：11 项通过。

## 未扩展范围

本轮没有预生成音频。正式 TTS 仍只在权威阶段开始后使用原有真双向流式链路，从而避免有限 GPU/云语音并发被后台任务占满。
