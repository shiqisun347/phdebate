# Round 6：产品、UI 与 React 稳定性审计

日期：2026-07-19  
范围：公开大厅、赛事详情、排行榜、个人中心、房间大厅、结果页、单场控制台和管理后台。比赛舞台、TTS、LiveKit、AudioWorklet 与浏览器连续播放路径保持冻结。

## 结论

当前运行页面已经以“赛事—房间—比赛—结果”为唯一业务主线，没有教师、课堂、课程、班级、全班或教学活动入口。本轮没有发现新的教学场景泄漏。

本轮直接修复了两个用户可感知的数据竞态，改善了个人中心空状态，并为长逐字稿和时间线补充了列表语义。改动不改变后端协议、房间状态机或任何实时语音代码。

## 本轮修复

### 1. 个人中心分页旧响应覆盖

快速点击“下一页”后立即返回上一页时，网络较慢的第二页响应可能最后到达，并把已经返回的第一页替换掉。现在每次载入拥有递增序号，只有最后一次请求可以更新页面、错误状态或登录跳转。

新增回归测试使用延迟 Promise 人为制造乱序响应，确认迟到页面不会覆盖当前页面。

### 2. 排行榜赛季切换竞态

用户快速选择不同赛季时，旧赛季请求可能晚于新赛季完成，造成选择框显示第三赛季、表格却显示第二赛季的错配。现在排行榜请求同样采用“最后请求胜出”规则，加载状态也只由当前请求关闭。

新增回归测试覆盖第二赛季迟到、第三赛季先完成的真实网络顺序。

### 3. 个人中心空状态缺少行动出口

“没有需要继续的比赛”和“还没有历史比赛”过去是终点文案。现在分别提供“选择赛事”和“参加第一场比赛”入口，并说明比赛完成后会保存逐字稿、结果和积分变化。空状态从单纯描述数据变为引导下一步任务。

### 4. 长记录的辅助技术语义

结果页完整辩论记录、比赛时间线和控制台自动流程时间线现在具有命名列表与列表项语义。空列表不错误声明 `role=list`，避免产生 ARIA required-children 错误。原有 `content-visibility` 屏外渲染优化保持不变。

## 赛事语义检索

对 `apps/api/app`、`apps/web/app`、`apps/web/components` 和 `apps/web/lib` 进行了教师、老师、课堂、课程、班级、全班、教学、教室及对应英文词检索。剩余命中仅包括：

- 测试中的“不得出现旧语义”反向断言；
- 历史 Alembic 迁移版本名；
- 后端用于过滤旧审计记录的退役前缀；
- 可靠语音保护文件中的历史注释，不进入界面、接口或数据。

这些内容不构成运行时产品功能，也不应为了文字清理而破坏数据库迁移链或可靠语音代码。

## 设计与工程原则

- 延续深蓝赛事品牌和高信息密度控制台，不引入通用模板式渐变、无意义大标题或装饰动画。
- 空状态必须回答“为什么为空”和“下一步能做什么”。
- 实时连接、比赛状态和可操作原因继续以文字表达，不只依赖颜色。
- React 异步请求以用户最后意图为准，避免请求乱序造成视觉与数据错配。
- 长列表先使用按需音频、游标补载和 `content-visibility`；达到更大数据量后再引入分页或虚拟化。
- 本轮没有复制第三方项目代码；产品结构继续遵循前轮从 Lichess、DMOJ、LiveKit、Colyseus 和 boardgame.io 提炼的任务分区、权威状态、身份绑定与恢复原则。

## 验证

- 定向测试：4 个测试文件、22 项通过。
- 全量前端在限制为 2 个 worker 时：34 个测试文件、227 项通过。
- 默认并发全量测试曾出现一次管理后台测试超过 5 秒，单独重跑 843ms 通过；这是测试机高并发资源竞争导致的时间敏感性，未发现产品逻辑失败。CI 建议固定合理 worker 数量，避免用放宽所有超时掩盖问题。
- ESLint：0 error；13 个既有 warning 均位于冻结比赛舞台、音频文件、其测试或 PostCSS 配置，本轮未改动。
- Next.js 生产构建与 TypeScript 检查通过。
- 未部署，未修改 `DebateStage`、`apps/web/lib/audio`、AudioWorklet、TTS、MOSS、LiveKit 或 FunASR 实现。
