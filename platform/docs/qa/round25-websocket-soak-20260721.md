## 发现和修复

1. 房间写接口在提交后读取房间，再持有同步 SQLAlchemy 读事务等待 Redis 广播。20 场并发时单实例出现 15 条 `idle in transaction`，连接池耗尽并使健康检查阻塞。广播前现会验证会话无待提交对象并释放尾随读事务。
2. 匿名观众 WebSocket 在 `SessionLocal` 作用域内等待 Redis 观众名额。400 个并发握手时旧实现仅 18 个完成，随后连接池耗尽。授权查询与 Redis 名额预留现已分离。
3. 已获准观众的 Redis 租约刷新超过 1 秒时，旧实现将其误判为超限并以 4429 断开。现在临时超时保留本地已获准租约；租约确实丢失时，通过全局原子限额重新登记。
4. 单次租约操作超时曾关闭整个共享 Redis 客户端，连带中断该实例全部房间 Pub/Sub。现在只有确定的连接错误才重建客户端；操作超时由调用方局部降级，不拆除健康订阅。
5. 压测工具原先只等待 15 秒检查异常断网租约，而生产租约 TTL 为 60 秒。验收窗口现覆盖完整 TTL，避免把正确的过期回收误报为泄漏。

上述变更未修改冻结的 TTS、实时语音或浏览器播放文件。
