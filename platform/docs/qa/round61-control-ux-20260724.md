# Round 61 单场控制与辩手体验验收

日期：2026-07-24  
范围：房间大厅、单场控制台、辩手页、观战页及共享比赛舞台  
结论：本轮范围内通过；未部署，未修改音频、ASR 或 TTS 内部实现。

## 本轮目标

- 让房主从“人员就绪”到“开始比赛”的下一步清楚、唯一且不会重复点击。
- 让准备、运行、暂停、恢复、跳过、重试和终止的状态与操作原因可直接理解。
- 让辩手在桌面端和 390×844 手机端始终能看到当前阶段、轮到谁、剩余时间以及按钮为何不可用。
- 保持观众不可见文字稿；观战页只显示公开舞台信息。
- 自由辩论单轮严格显示为最多 30 秒，即使服务端或旧测试快照仍携带 40/45 秒旧值。
- 真人席位不允许 AI 自动接管；真人断线满 60 秒后整场自动暂停，全部真人重新连接后由房主或管理员显式继续。

## 已修复问题

1. 房主就绪后的“开始比赛”曾与普通次要操作视觉接近。现在使用唯一蓝色主操作，并在页面和确认框中说明：只需点击一次，系统会锁定席位、补齐原本为空的 AI 席位、建立实时语音、播放预设开场提示，再自动进入第一阶段；准备期间不启动比赛计时。
2. `preparing` 容易被理解为比赛卡住。大厅、控制台和比赛舞台现在统一说明“正在建立实时语音并加载预设提示音，计时尚未开始，无需再次点击”。
3. 控制台部分禁用按钮只有灰色状态，没有解释。跳过、终止、移交房主和重置 AI 发言现在均提供可见且可被辅助技术读取的具体原因，例如真人正在发言、真人仍离线、系统正在自动暂停、比赛已结束或上一项操作尚未完成。
4. 辩手页的主要发言按钮会直接显示阻塞原因，例如“等待周亦然开始发言”“等待实时连接”“等待全部真人重连”，不再要求学生猜测状态。
5. 旧房间快照可能把自由辩论单轮显示为 40/45 秒。共享舞台现在把投影值限制在 0–30 秒，等待阶段显示 `00:30`，权威开始后正常倒计时。
6. 桌面底部工具栏中的“文字记录”可能被挤成两行。按钮现在禁止换行且不被 flex 压缩；手机端仍只显示图标，避免占用主操作空间。
7. 发言按钮的具体禁用原因原先会被单行省略。现在最多显示两行，在不放大底部控制区的前提下保留完整原因。

## 关键状态验收矩阵

| 场景 | 页面应显示 | 允许操作 |
| --- | --- | --- |
| 大厅未就绪 | 明确列出未就绪席位 | 本人准备；房主不能开始 |
| 大厅全部就绪 | 蓝色“开始比赛”，并说明只需点击一次 | 房主确认开始 |
| 比赛准备中 | 实时语音/预设提示音准备中，计时未开始 | 不允许重复开始、跳过或发言 |
| 固定轮次等待他人 | 当前发言人姓名和完整禁用原因 | 当前用户不可发言 |
| 自由辩论举手窗口 | 底部举手操作和最多 3 秒窗口 | 符合条件的当前阵营辩手举手 |
| 自由辩论获得轮次 | 主按钮显示开始发言，单轮最多 `00:30` | 获得轮次的真人辩手开始发言 |
| 真人正在发言 | 主按钮切换为结束发言，显示剩余时间 | 本人结束/修订；房主不能普通暂停或跳过 |
| 真人断线未满 60 秒 | 真人身份和席位保持，显示自动暂停倒计时 | 不创建替代 AI 发言 |
| 真人断线满 60 秒 | 整场自动安全暂停，保留已确认文字 | 全部真人重连前禁止恢复/重试 |
| 全部真人已重连 | 仍保持暂停，提示房主确认现场 | 房主或管理员显式继续 |
| 服务异常暂停 | 显示异常原因和推荐重试动作 | 不把异常暂停误当普通恢复 |
| 比赛结束 | 控制动作显示结束原因 | 不允许继续、跳过或移交控制 |
| 匿名观战 | 只读比赛舞台 | 无麦克风、控制和文字记录入口 |

## 边界说明

- “AI 补齐空席”只发生在开赛锁定时，属于比赛阵容配置；已经绑定真人的席位不会被 AI 接管、转换或释放。
- 60 秒断线暂停由服务端权威状态机执行，前端倒计时仅用于说明，不能绕过或延后服务端暂停。
- 观众文字稿隐藏规则未改变。
- 本轮未部署，也未改动实时语音、播放器、ASR、TTS 或 Agent 内部链路。
