# Round 20 主持人口播阶段

日期：2026-07-21

## 结论

内置 `4v4 人机辩论正式赛` 与 `1v1 辩论训练赛` 的新建房间，现会在开场及每个正式发言、自由辩论、裁判阶段前播放主持人口播。口播由目标阶段内部的服务端权威门控管理：阶段 key 和索引保持不变，但口播结束前真人按钮、Agent 和裁判都不能启动。

## 实现

- 内置自动流程升级为版本 3；历史房间继续使用创建时冻结的旧快照，既有阶段索引保持兼容。
- 系统只自动升级仍绑定内置旧版本流程的赛事；管理员已经发布的更高版本不会被启动 seed 覆盖。
- 主持人口播在开赛准备期统一生成，若管理员上传了 key 与文字都匹配的 `AudioCue`，优先复用预设 WAV。
- 状态机使用已准备 WAV 的真实时长加 750ms 交付余量锁定目标阶段，避免模板估算过长造成空等，也避免正常调度延迟裁掉尾字。
- 暂停会冻结剩余口播时间，恢复后继续门控；跳过、终止和换阶段不会让旧口播重新开放发言。
- 自由辩论口播明确提示发言申请和三秒换方窗口。
- 两类内置赛事的新流程都把自由辩论单次发言上限统一为 30 秒。

## 验证

- 新建训练房间的每个 `speech`、`free`、`judging` 阶段都包含非空主持人口播 cue，但不增加额外阶段索引。
- 2 秒测试 WAV 会形成约 3 秒的权威阶段窗口，而不是沿用 30 秒模板占位时间。
- 自动流程版本化回归确认：管理员发布的新版本在再次 seed 后仍保持绑定。

定向测试：3 passed。

## 边界

本轮没有修改已冻结的实时 TTS、LiveKit 音频发布、浏览器连续播放器或 AudioWorklet。语速、撕裂音和比赛中卡顿需继续沿既有可靠语音基线以生产录音和浏览器播放遥测定位，不能通过在网页端临时加速或分片重播规避。
