# Round 66 退役路径与运行时简化审计

日期：2026-07-24

## 结论

当前用户产品只有一组赛事与房间路由，没有可达的 `v2`、教师、课堂、课程或主持人页面。真人席位没有 AI 自动接管运行路径；浏览器实时麦克风上行不使用 `MediaRecorder`。本轮删除了生产 Nginx 中最后一个主持人兼容入口，并将这些要求变成持续自动化防回归门。

## 本轮改动

- 从两份生产 Nginx 配置删除旧 `/room/:code/host` 跳转；旧 `admin/control` 地址仍只跳转到当前房间控制台。
- 管理端“阶段预设语音”文案改为正式规则：只复用提前制作的系统语音，缺失时安全暂停，不在赛中临时换音色。
- MOSS 生产发布门新增强制条件：
  - `HOST_CUES_PRESET_ONLY=true`
  - 任何环境值不得配置端口 `6016`
  - 任何环境值不得配置 `Qwen3 8B`
  - 拒绝时只报告字段名，不回显 URL、密钥或其他配置值。
- Web 防回归审计从手写页面清单改为遍历全部实际 `page.tsx`，后续新页面也会被检查。
- Web 防回归新增全运行时扫描：禁止 `MediaRecorder`，禁止结果页音频播放器，并限制文件播放只能用于预先制作的系统阶段提示。
- 清理了当前运行时注释和初始迁移标题中的课堂、V2 产品遗留命名。

## 可复现证据

当前 Next.js 用户页面只有：

- `/`、`/login`、`/register`、`/me`、`/rankings`
- `/competitions/:slug`
- `/rooms/:code/lobby|debate|watch|control|result`
- `/admin`、`/admin/agent-access`

静态扫描结果：

- 非测试 Web 运行时 `MediaRecorder`：0 处。
- 非测试 Web 运行时 `new Audio(...)`：1 处，仅用于 `audio.cue.ready` 系统预设提示；AI 正文仍只订阅 LiveKit 连续音轨。
- API/Web 当前运行时 `ai_substitute`、`seat.restore_*`、`seat.ai_substituted`：0 处。
- 所有当前页面文本中“教师/课堂/课程/教学活动/主持人”：0 处。
- 两份跟踪的 Nginx 配置中 `/v2`、`|host`、`6016`、`Qwen3-8B`：0 处。

## 测试

- Web 定向回归：11 passed。
- 部署配置与 MOSS-only 发布门：20 passed。
- API 赛事域、退役音频上传、无 AI 接管、Qwen3 8B 拒绝：5 passed。

## 有意保留，未盲目删除的内容

- Alembic 中已执行的历史迁移、AI 接管清理迁移和其测试：用于把旧数据库正规化到现规则，不是可达的运行功能。
- `legacy` 比赛只读导入和结果兼容：用于保留历史文字记录，管理端不能启用或修改这些比赛。
- 恢复清单中的 `v2_database` 旧 schema 角色名：只用于识别、验证和隔离旧备份；删除会使已有恢复集无法审计。
- LightTTS 类、配置解析和测试：当前生产发布门已禁止启用其流式路径，但历史比赛快照、数据迁移和本地隔离测试仍依赖它。在完成历史快照升级前整块删除会破坏恢复能力。
- WAV 处理：比赛发言录音已默认不保存，但系统阶段提示是管理员提前生成、所有房间复用的固定 WAV，符合当前产品要求。
- `debate-agent/`：这是按需求独立部署的 Agent 管理服务，不是第二个辩论用户平台。

## 后续债务

系统阶段预设提示目前仍通过唯一的 HTML Audio 文件播放器播放，而 AI 正文通过 LiveKit WebRTC 连续音轨播放。它们不会在一次 AI 发言中切换播放器，但从整场比赛的音频架构看仍是两类下行。若要完全实现“整场只有一条 WebRTC 音轨”，后续需将固定提示文件也由服务端发布到同一 LiveKit publisher。该改动会涉及比赛引擎和 `DebateStage`，本轮按并行修复冲突约束没有修改。
